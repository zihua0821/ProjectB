**版本**: v1.0  
**更新日期**: 2026-08-04  
**分支**: MassCrop  
**关联系统**: Plot（地块）、Crop（农作物）

---

## 一、系统概述

### 1.1 语义定义

**单元格（Cell）** 是行星表面经纬网格划分的最小单元。在视觉上，单元格通过一个**半透明高亮面片**（`OutlineMesh`）呈现，仅在以下场景显示：

- **鼠标悬停**：玩家将鼠标移动到某单元格上时，显示该单元格的高亮面片
- **多选（规划中）**：未来的多选交互需要同时高亮多个单元格

单元格**不是常驻可见的实体**——未悬停时面片完全隐藏。

> 该面片本质是一个**正方形平面面片**：创建实例时通过 CustomData 传入四个实际角点坐标，材质端通过顶点偏移将其弯曲为贴合球面的**梯形面片**（详见 [4.2 面片几何与顶点偏移](#42-面片几何与顶点偏移核心渲染原理)）。

### 1.2 三大系统的边界

| 系统 | 语义 | 视觉载体 | 状态数据 |
|------|------|---------|---------|
| **Cell（单元格）** | 行星表面网格单元 | `OutlineMesh`（半透明轮廓） | `FHighlightFragment` |
| **Plot（地块）** | 耕地后的格子 | `LandCellMesh`（土地网格） | `FPlotStateFragment` |
| **Crop（农作物）** | 种植的作物 | 作物各阶段 Mesh（增量池） | `FCrop*Fragment` |

> 三者共享同一个 `UCellManagerComponent` 管理的 Mass 实体，但通过不同的 Fragment 组合区分角色，由不同的 Processor 负责各自的可视化同步。

### 1.3 关键设计点

- **面片几何**：轮廓网格本质是正方形平面面片，创建时传入四个实际角点坐标（CustomData[4..15]），材质通过顶点偏移形成贴合球面的梯形面片
- **轮廓样式**：可通过材质端挖空面片中心实现"轮廓框"样式，但实际观感不佳，**已弃用**；当前表现为半透明面片
- **透明度固定为 0.1**（刻意设计）：半透明显示，避免遮挡单元格内容
- **颜色随编辑模式变化**：如耕地模式黄色、灌溉模式蓝色、重置模式红色等
- **材质禁用深度测试**：保证面片不被星球表面等其他物体遮挡
- **通过 CustomData 控制显隐与颜色**：CustomData[0]=Opacity，[1..3]=RGB

## 二、架构设计

### 2.1 模块组成

```
┌────────────────────────────────────────────────────────────┐
│                     UCellManagerComponent                    │
│  (挂载于 APlanetActor，负责创建实体 + 初始化 ISM + 交互转发)   │
└────────────────────────────────────────────────────────────┘
        │ 创建 Mass 实体
        ▼
┌────────────────────────────────────────────────────────────┐
│                    Mass Entity（每个单元格一个）              │
│  FCellStaticFragment  —— 静态数据：坐标/变换/类型            │
│  FHighlightFragment   —— 高亮状态：显隐/颜色/影子副本         │
│  共享渲染 Fragment    —— 地块/作物渲染 ID（供其他系统复用）    │
└────────────────────────────────────────────────────────────┘
        │ 读取 Fragment 变化
        ▼
┌────────────────────────────────────────────────────────────┐
│                 UCellVisualSyncProcessor                    │
│  检测 bHighlighted / HighlightColor 变化 → 增删改 ISM 实例   │
└────────────────────────────────────────────────────────────┘
        │ 写入
        ▼
┌────────────────────────────────────────────────────────────┐
│  UISMManager（WorldSubsystem）→ OutlineMesh 的普通 ISM 组件  │
└────────────────────────────────────────────────────────────┘
```

### 2.2 Fragment 定义

**`FCellStaticFragment`**（`Mass/CellMassFragments.h`）— 单元格静态数据，初始化后几乎不变：

```cpp
USTRUCT(BlueprintType)
struct FCellStaticFragment : public FMassFragment
{
    FIntPoint Coords;        // 网格坐标（LatIdx, LonIdx），稳定索引
    FTransform Transform;    // 世界空间变换（球面位置、朝向、缩放）
    ECellType CellType;      // 单元格类型（Empty/Crop/Warehouse/...）
};
```

**`FHighlightFragment`** — 高亮状态，由 `UCellManagerComponent` 写入、`UCellVisualSyncProcessor` 消费：

```cpp
USTRUCT(BlueprintType)
struct FHighlightFragment : public FMassFragment
{
    FGlobalInstanceId InstanceId;     // 当前轮廓 ISM 实例稳定 ID
    bool bHighlighted = false;        // 是否需要高亮
    bool LastHighlightedState = false;// 影子副本：上次高亮状态
    FLinearColor HighlightColor;      // 高亮颜色
    FLinearColor LastHighlightColor;  // 影子副本：上次颜色
};
```

> **影子副本机制**：`LastHighlightedState` / `LastHighlightColor` 用于检测"状态是否变化"，避免每帧无意义的 ISM 写入（详见开发实践规范"使用影子副本优化查询性能"）。

### 2.3 ISM 组件配置

轮廓组件在 `UCellManagerComponent::PrecreateISMComponents()` 中创建：

```cpp
FISMComponentParams CellISMParams;
CellISMParams.AttachParent = this;
CellISMParams.bDisallowNanite = true;   // 关闭 Nanite（材质需要 CustomData 控制透明度）
CellISMParams.bCastShadow = false;      // 关闭阴影投影
ISMManager->GetOrCreateISMComponent(FarmlandConfig->OutlineMesh, 16, CellISMParams);
```

- **普通 ISM**（`bUseIncrementalISM` 不设置，默认 false）
- **16 个 CustomData floats**（与 `CellOutlineCustomData` 枚举一一对应）
- 挂载父组件为 `UCellManagerComponent`（位于星球 Actor 上，局部原点）

## 三、数据流（渲染链路）

### 3.1 实体创建

`UCellManagerComponent::CreateMassCell()`（`CellManagerComponent.cpp` L143-274）：

1. 计算单元格数量：`(NumLat - 1) * NumLon`
2. 批量创建 Mass 实体（Archetype 含 CellStatic / Highlight 及共享渲染 Fragment）
3. 遍历经纬网格，计算每个单元格的世界坐标（球面投影）与朝向（径向朝外）
4. 写入 `FCellStaticFragment`（坐标、变换、类型）
5. **说明**：轮廓实例此时**不创建**（`bHighlighted=false`），只在悬停时按需添加

### 3.2 高亮触发链路

```
BasePlayerController::Tick（每帧）
    └─ UpdateHoveredPlot()
        ├─ TraceForFarmlandAndCell()   ← 射线检测（ECC_WorldDynamic）+ 球面求交算坐标
        │    └─ GetCellCoordsFromScreenMouse()  ← 射线与球面二次方程求交 → LatIdx/LonIdx
        └─ HitPlanet->OutlinePlot(Coords, true)
            └─ CellManagerComponent->UpdateOutline(Coords, bEnable)
                └─ Defer 命令：修改 FHighlightFragment（bHighlighted + HighlightColor）
```

**关键点**：

- 射线检测命中的是星球球体（`SphereMeshComponent`），随后用**球面数学求交**计算单元格坐标，不依赖 ISM 碰撞
- `TraceForFarmlandAndCell` 只查询 `ECC_WorldDynamic`，星球球体碰撞类型需为 WorldDynamic
- `UpdateOutline` 通过 Mass 的 Defer 命令延迟修改 Fragment（帧末生效），避免与处理器竞争
- `UpdateHoveredPlot` 有去重优化：`PreHoveredPlotCoords == CellCoords` 时直接返回

### 3.3 视觉同步（UCellVisualSyncProcessor）

`CellVisualSyncProcessor.cpp` 每帧执行：

```
ForEachEntityChunk（需求：FCellStaticFragment + FHighlightFragment）
    ├─ bHighlightChanged？ → PendingAdds（添加高亮面片实例）/ PendingRemoves（移除）
    ├─ bColorChanged？     → PendingUpdates（更新颜色 CustomData）
    └─ 更新影子副本（LastHighlightedState / LastHighlightColor）

批量提交：
    ├─ BatchRemoveInstances(OutlineMesh, PendingRemoves)
    ├─ BatchAddInstances(OutlineMesh, Transforms, 16, params, CustomData)
    │   └─ 写回 FHighlightFragment.InstanceId
    └─ BatchSetInstanceCustomData(OutlineMesh, Ids, CustomData)
```

**轮廓 CustomData 布局**（16 floats）：

| 索引 | 含义 |
|------|------|
| 0 | Opacity（**固定 0.1**，半透明面片） |
| 1-3 | R / G / B（编辑模式颜色） |
| 4-15 | 单元格四个角点的球面坐标（X/Y/Z × 4），材质端用于顶点偏移，将平面面片弯曲为球面梯形 |

### 3.4 时序说明

- 悬停触发 → Fragment 修改（Defer，帧末） → 下一帧 Processor 检测到变化 → ISM 写入 → 渲染
- 整体延迟 **1 帧**，对交互反馈可接受

## 四、关键实现细节

### 4.1 经纬网格坐标系统

- 纬度：`MinLat ~ MaxLat`，共 `NumLat` 条纬线 → `NumLat - 1` 个纬度间隔
- 经度：`0° ~ 360°`，共 `NumLon` 个经度间隔
- 单元格坐标：`(LatIdx, LonIdx)`，`LatIdx ∈ [0, NumLat-2)`，`LonIdx ∈ [0, NumLon)`
- 扁平索引：`FlatIndex = LatIdx * NumLon + LonIdx`

### 4.2 面片几何与顶点偏移（核心渲染原理）

单元格高亮网格（`OutlineMesh`）本质是一个**正方形平面面片**，其渲染流程如下：

1. **CPU 侧（计算角点）**：`CellVisualSyncProcessor::CalculateCellVertexPositions()` 根据经纬网格边界计算单元格四个角点在球面上的实际位置（经纬度 → 球面坐标），按 `X00/Y00/Z00、X01/Y01/Z01、X10/Y10/Z10、X11/Y11/Z11` 的顺序写入 CustomData[4..15]
2. **GPU 侧（顶点偏移）**：材质通过顶点偏移（World Position Offset）读取四个角点坐标，将平面面片的顶点移动到对应角点位置，使面片弯曲为**贴合球面的梯形面片**
3. **轮廓样式（可选，已弃用）**：材质端可通过挖空面片中心区域形成"轮廓框"样式，但实际观感不佳，**已停用**；当前实际渲染为半透明面片

> 角点顺序约定：V1=南西、V2=南东、V3=北西、V4=北东（对应 `CalculateCellVertexPositions` 中的 LatDegrees / LonDegrees 数组）。
> 材质已**禁用深度测试**，保证面片始终可见、不被星球表面等其他物体遮挡。

### 4.3 轮廓实例变换（CalculateOutlineInstanceTransform）

- 依据 `PlanetConfig` 计算单元格实际尺寸（球面几何）：
  - 南北向高度 = `Radius × LatStepRad`
  - 东西向宽度 = `Radius × cos(纬度) × LonStepRad`
- 依据 `OutlineMesh` 自身包围盒计算缩放，使轮廓贴合单元格
- 在单元格变换基础上叠加 `OutlineOffsetZ` 抬升，避免与地面 z-fighting

### 4.4 编辑模式颜色映射

`GetOutlineColorForEditMode()`（`CellManagerComponent.cpp` L864-927）：

| 编辑模式 | 颜色 | 编辑模式 | 颜色 |
|---------|------|---------|------|
| Plow（耕地） | 黄 | UnPlow | 红 |
| Wet（灌溉） | 蓝 | UnWet | 红 |
| Fertilize（施肥） | 灰 | UnFertilize | 红 |
| Weed（杂草） | 绿 | UnWeed | 红 |
| Pest（虫害） | 灰 | UnPest | 红 |
| PlantCrop / HarvestCrop | 黄 | RemoveCrop | 红 |
| Reset / 其他 | 白/红 | CropDried | 灰 |

切换编辑模式时，`OnEditModeChanged` 会通过 Defer 命令更新当前高亮单元格的 `HighlightColor`。

## 五、技术选型：为什么使用普通 ISM 而不是增量 ISM ？

### 5.1 场景分析

| 维度 | 单元格轮廓（Cell） | 农作物（Crop，对照） |
|------|-------------------|---------------------|
| 同时实例数 | 1 个（未来多选几十个） | 上千个 |
| 更新频率 | 悬停切换（低频） | 生长阶段 + 状态变化（中频） |
| 更新类型 | 显隐 + 颜色 | Transform + CustomData |
| 全量重建成本 | 组件内实例极少 → 可忽略 | 组件内上千实例 → 昂贵 |

普通 ISM 的 `MarkRenderStateDirty()` 全量重建成本与**组件内实例数**成正比。轮廓组件同时只有 1 个实例（未来几十个），重建开销可以忽略，**增量 ISM 的收益在当前场景下不成立**。

### 5.2 结论

- **当前阶段**：普通 ISM 足够，实现简单、路径可靠（父类接口一定生效），避免"写了不显示"的坑
- **未来多选**：若多选同时高亮几十个单元格且实测出现性能问题，可再评估切换增量 ISM + 对象池（`AcquireSlot/ReleaseSlot` + `FlushAllIncrementalComponents`），Crop 系统已有成熟范式可参考
- **切换代价**：若未来迁移，需同步修改 `CellVisualSyncProcessor` 的增删改接口（仅支持增量组件的池接口），并保持 `NumCustomDataFloats=16` 一致

### 5.3 与增量 ISM 的适用边界（经验总结）

| 场景 | 推荐模式 |
|------|---------|
| 高频显隐/变色、实例数少 | 普通 ISM（如单元格轮廓） |
| 高频更新、实例数大 | 增量 ISM + 对象池（如农作物） |
| 未来批量多选高亮 | 视实例数量级决定，可平滑迁移 |

## 七、已知问题与注意事项

1. **CustomData 数量一致性**：`BatchAddInstances` 对 `CustomData.Num() == 实例数 × NumCustomDataFloats` 有严格校验，不匹配则静默跳过。轮廓固定 16 floats，与组件 `NumCustomDataFloats=16` 一致。
2. **Defer 时序**：`UpdateOutline` 的 Fragment 修改延迟一帧生效，Processor 在下一帧检测到变化，整体 1 帧延迟。
3. **射线碰撞类型**：悬停检测依赖星球球体碰撞为 `ECC_WorldDynamic`，若球体改为 WorldStatic 则悬停失效。
4. **Defer lambda 捕获**：`UpdateOutline` / `OnEditModeChanged` 的 Defer 命令引用了 `this`（组件），组件生命周期需长于 Mass 实体（当前挂在 PlanetActor 上，满足）。
5. **透明度与深度测试**：面片透明度固定 0.1（设计值），修改需同步确认材质端的 Opacity 处理；材质已禁用深度测试以保证面片不被遮挡，若需要恢复遮挡关系需重新评估。
6. **`GetCellCoordsFromScreenMouse` 的边界保护**：纬度钳制到 `[0, NumLat-2]`，经度取模 `NumLon`，射线未命中球面时返回 false。
