## 二、三条链（本模块全部内容）

### 链① 编辑提交（面板 → 重建）
```
SOrbitEditorPanel 参数控件（回车/失焦提交——注意 Slate 回调顺序·易错点 #19）
  → PushWorkingDataToManager（编辑副本 → 运行时数据；可视化实时预览）
  → Controller->CommitOrbitChanges（PC L442）
  → Manager->ApplyOrbitChangesForOrbit（M-3 L522——按轨重建）
拖动场景：RequestThrottledRebuild（0.2s 节流——防每帧重建）
（历史注：原 Apply 按钮已删——统一"提交即重建"；M3 删除的全量入口不在链路中）
```

### 链② 选定暂停（编辑模式的总闸门）
```
进入：PC EnterOrbitEditMode（L226）→ SimControl 置暂停 → 可视化开 + 悬停互斥
      → 【白名单冻结】Plan/Slot/Movement/Heartbeat/CropGrowth（M-2 §3.6，宏 L44）
退出：PC ExitOrbitEditMode（L263）→ SimControl 解除
      → 【时间基准重置】Manager->ResetSatelliteStateTreeTimeBase（M-3 L564——防恢复瞬移·易错点 #18）
      → 可视化收 + OrbitCoverageVisual 刷新
暂停语义：只持状态位；参与者各自在 tick 入口查宏（无广播——拉模型）
```

### 链③ 覆盖可视化（订阅驱动的重建）
```
Initialize（L40）→ 订阅 Manager->OnRuntimeOrbitChanged（HandleRuntimeOrbitChanged L135）
数据变更（编辑/新增/删除轨）→ 广播 → 重建：
  RebuildOrbitVisual（L178）：轨道环 + 服务距离范围圆柱（ISM 实例——M-5 接口）
  ComputeCoveredCells（L346）：逐格 IsPointInOrbitCoverage（M-7）→ 覆盖格集合
  RebuildCellHighlight（L407）：覆盖格高亮实例（多轨冲突取列表序靠前）
删除轨：RemoveOrbitVisualInstances（L140）；全清：RemoveAllVisualInstances（L170）
SetVisualizationEnabled（L59）：编辑模式开关（聚焦性能）
```

### 专题讨论一：RebuildCellHighlight 的复杂度（10-09 用户提出）

```
现状（三段 diff）：旧遍历找“旧有新无”→清；新遍历找“新增/变色”→写；Map 整体拷贝。
两层 diff 链：① 本函数 diff（Map→fragment）② CellVisualSync 自身 diff（fragment→实例）。
复杂度实估：≤432 格 × 双遍历 + 格级 O(1) 访问；节流 0.1s——运行量级很低（主要是【代码结构观感】）。

diff 存在的真实动机（读透后归因）：
① 避免触碰“仍覆盖”的交集格——因 bHighlighted/HighlightColor 与【悬停高亮共用同一 Fragment】
   （编辑模式中悬停互斥——理论上交集格不会被悬停占用；但保守回退）
② 变色检测（轨道列表序变化→归属色变）

候选方案：
· A 保持 diff + 结构整理（提取集合差辅助）——小改善
· B【当前倾向】简化“两段全量写”（去 diff）：旧集合全清 + 新集合全写
  依据：① fragment 写无副作用（值不变→CellVisualSync 二级 diff 不响应）；
       ② 同函数原子性——“先清后写”中间态同帧不可见；③ 规模小（≤432）+ 节流 0.1s。
  前提声明（注释）：悬停与覆盖运行时互斥（编辑模式无悬停）
· C【根治·可后续】覆盖高亮用独立通道（独立 Fragment/字段）——彻底解除与悬停的共用耦合；
  改动面：Fragment 定义 / CellVisualSync 读写 / 两处写入方——可作为后续重构项登记
状态：【10-09 裁定：维持原逻辑】——B/C 不做；执行①（混合色）时可顺便做结构整理（不改变 diff 逻辑）；【C 通道分离 → 登记为后续项】
```

### 专题讨论二：多轨重叠区域的覆盖色语义（10-09 用户发现“未定义行为”）

```
现状链：ComputeCoveredCells 逐格遍历轨道（内层）→ 首个命中即 break（列表序靠前胜出）。
列表序 = RuntimeOrbits 数组序（创建序；RemoveOrbit 后压缩变动）。
默认色：全轨道 VisualColor（蓝）/ CoverageColor（金）相同——“按轨道序自动分配”无实现（注释失准）。

真实影响：① 默认同色时：重叠区与非重叠区无视觉差异（规则不可见）；
② 用户改色后：重叠区显示“靠前轨道色”——用户不知规则，且轨道增删会改变归属（不稳定/不透明）。

候选语义（已裁定——方案①，见下）：
· ① 混合色：重叠格 = 覆盖它的全部轨道色平均/混合（稳定且与序无关；“混色”自然表达“多轨参与”）
· ② 重叠标识色：重叠格用统一特殊色（如白）——强提示“冲突区”（编辑时注意到重叠）
· ③ 稳定优先级：保持单色但改用确定性排序（如轨道名）——稳定但仍不表达“重叠”
· ④ 交互式（编辑面板选中某轨→只显示该轨覆盖）——最佳编辑体验；属 UI 交互项（可后续）
AI 推荐：①（最小成本：稳定、信息完整；与现高亮链路零冲突）——或 ①+④ 组合（后续）。
【10-09 裁定：方案①混合色】—— 实现要点：内层循环收集【全部】命中轨道色 → 求平均（FLinearColor 平均运算；去“break 首个命中”）；与列表序无关（稳定）；④ 交互式作后续增强项。
```

## 附三：UMG↔Slate 包装机制速览（对照 UOrbitEditorWidget·10-09）

```
【两层】UMG（UWidget）= 配置壳（蓝图可见/显隐/生命周期）；Slate（SWidget）= 实际控件（渲染/交互）
【术语精确】对外的取用入口 = TakeWidget（引擎注：“获取底层 Slate 控件；不存在则构造它——
  要替换“构造出什么”看 RebuildWidget”）；RebuildWidget = 构造执行点（子类实现的虚函数——
  引擎注：“当底层 SWidget 需要被构造时被调用”）——“Rebuild”源于可重构造设计（缓存失效可重调；首次调用即 Build）
【四个接口】RebuildWidget（构造执行点·虚函数）/ TakeWidget（对外取用入口·框架门面·非重写）
  / ReleaseSlateResources（释放回调）/ SynchronizeProperties（属性同步·构造后调用）
【调用链】组件入树显示 → TakeWidget →（缓存 MyWidget 无效）→ RebuildWidget → 返回 SWidget
  → 交 Slate 树插入布局 → 移除/销毁 → ReleaseSlateResources
  （惰性构建：首次布局时调用；显隐走 Slate Visibility，不经 RebuildWidget）
【本组件】RebuildWidget：SNew(SOrbitEditorPanel)（SLATE_ARGUMENT 传 PC + SLATE_EVENT 绑 OnCloseRequested）
  → return OrbitPanel.ToSharedRef()；ReleaseSlateResources：OrbitPanel.Reset()
  （与引擎原生控件做法一致：直接返回自定义 SWidget，无需 SObjectWidget 包装）
【双向通信】下行：蓝图 SetVisibility → UMG 透传 Slate
  上行：× 按钮（Slate）→ OnCloseRequested 委托 → UMG 层（收起 + ExitOrbitEditMode）——面板“抛请求”，宿主处理
  数据：面板 → PC 接口（C++ 直调，经 friend）
【缓存与所有权（MyWidget·源码 Widget.cpp L977-1058）】TakeWidget_Private 内：
  if (!MyWidget.IsValid()) { PublicWidget = RebuildWidget(); MyWidget = PublicWidget; bNewlyCreated=true; }  ← 赋值点
  return PublicWidget.ToSharedRef() ← 强引用交给调用方（父容器/布局）——真正的所有权在 Slate 树
  · UWidget（UObject）不能强持有 SWidget（非 GC 体系）——只能 TWeakPtr 弱观察
  · 控件生死由 Slate 树决定：移除→销毁→MyWidget 失效→下次 TakeWidget 重走 RebuildWidget（“Rebuild”闭环）
  · SObjectWidget 包装仅 UUserWidget 走（源码 L1000-1001：user widget 才包，保 GC）；普通 UWidget 直接返回
  · bNewlyCreated 时：SynchronizeProperties() → OnWidgetRebuilt() 依次调用；GetCachedWidget()=只看不建
【为什么赋值点在 TakeWidget 而非“构造/BeginPlay”】UWidget 非 Actor（无 BeginPlay）；UObject 构造期=CDO/设计期
  不允许建 Slate；“何时需要真实控件”由使用方（父容器/视口）决定 → 惰性构建是唯一自洽模型
【SLATE 参数宏（声明式构造参数·10-09）】SLATE_BEGIN_ARGS…SLATE_END_ARGS 在类内生成嵌套 FArguments（构造参数集）：
  · SLATE_ARGUMENT(Type,Name) = 数据参数；SLATE_EVENT(DelegateType,Name) = 事件参数（语义区分，机制同）
  · 变体 SLATE_ATTRIBUTE(Type,Name) = 动态属性参数（TAttribute 运行期求值；本项目未用）
  · 消费链：SNew(Class).Arg(…).Evt(…) → 框架创建控件 → Construct(InArgs) 从 InArgs._Arg 取值
  · 动机：Slate 控件参数多且全可选——命名参数模式免构造重载爆炸；BEGIN_ARGS 的 {} 内可写默认值
  · 本项目：.PlayerController（弱指针·数据）/ .OnCloseRequested（宿主处理关闭）
```
