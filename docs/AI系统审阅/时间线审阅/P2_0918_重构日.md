## ③ 关键实现与决策点

### 3.1 d26ab5e：处理器 switch → StateTree 三任务（职责分离）

**迁移对照（先验证"逻辑搬家"的完整性——回应 P1 报告观察 O2）**：

| 旧 `SatelliteTaskProcessor`（P1） | 新 StateTree 任务（P2） | 迁移情况 |
|---|---|---|
| `TryAcquireTarget`（最近格→成熟检测→认领→写目标/角度） | `FSatelliteSelectTargetTask::Tick` | **逐行平移**（含注释），仅返回值改为 Succeeded/Running |
| `TryExecuteTask` 开头到达检测（MoveState==Paused） | `FSatelliteMoveToTargetTask::Tick` | 平移（独立成"等待"任务） |
| `TryExecuteTask` 执行段（收获→释放→清理→回巡航） | `FSatelliteHarvestTask::EnterState` | 平移（改在 EnterState 一次性执行） |
| `switch (Task.TaskState)` 的调度 | ST_Satellite 资产的状态转移 | 从代码搬到资产 |

→ **确认为"逻辑搬家"而非"逻辑重写"**；`ESatelliteTaskState` 枚举随之删除（fragment 注释改为："任务状态由 StateTree 资产编排，不再存于 fragment"）。

**新增：心跳处理器**（`SatelliteStateTreeTickProcessor.cpp`，48 行）：
```cpp
// 收集全部卫星实体（chunk 并行 + 锁合并）
// 每帧发送推进信号：
SignalSubsystem.SignalEntities(UE::Mass::Signals::NewStateTreeTaskRequired, SatelliteEntities);
//（UMassStateTreeProcessor 已订阅此信号 → 对相应实体跑 StateTree Tick）
```
- **决策背景**：Mass StateTree 是**信号驱动**——没有信号不 Tick。巡航选点、等待到达这类"持续轮询"任务必须外部每帧驱动。
- Movement 处理器同步删掉了 `ExecuteAfter("SatelliteTask")`（任务处理器没了；驱动改由心跳承担）。

**决策点**：
- **职责分离**（本提交的核心目的）：状态机编排归资产（转移条件可配）、任务只做"单状态内职责"、跨任务数据经 `FMassSatelliteTaskFragment` 传递——后续所有状态机工作沿用此分工
- **保留了 `MoveState` 的双职责残留**：`TaskState` 删了，但 `MoveState`（Idle/MovingToTarget/Paused）继续承担"移动意图 + 到达信号"两重语义（MoveToTarget 任务靠 `MoveState==Paused` 判到达）——⚠️ 隐患**未彻底解决**（P6 才用单状态定稿）
- Build.cs 增 `MassSignals` 依赖

### 3.2 66da5ec：玩家共享认领 + 旧系统退役

**玩家认领守卫**（`BasePlayerController::ExecuteEditModeWithClaim`，改造自原直通点击）：
```cpp
分支 1：无智能对象系统 / 操作不适用认领（None/Count）→ 直接执行
分支 2：目标 Slot 未启用（未耕地/未播种，对象不存在）→ 直接执行（创建类操作无竞争）
分支 3：已启用 → TryClaimSlot(High 优先级)：
         失败（被同级/更高占用）→ 拒绝本次操作（Warning 日志）
         成功 → 执行操作（同帧瞬时完成）→ 立即释放
```
**配套接口**（SmartObjectManager）：
- `IsSlotEnabled`（GetSlotView().IsEnabled()）
- `GetSlotIndexForEditMode`（静态映射：作物类操作→Crop Slot=1；地块类→Plot Slot=0；None/Count→-1）——**操作枚举与槽位体系的正式接线**

**旧系统退役清单**：
```
删除 C++：AutomationSatellite（-49/-53）/ SatelliteAIController（-28/-28）/
          OrbitMovementComponent（-115/-91）/ FarmPrototype（-214/-138）  + SmartObjectManager 相关引用
资产与源码移动：BTDecorator_* / EQS* / BTService_* / BTTask_* → docs/参考/旧AI行为树/（存档，含 9 个 uasset 删除）
```
- **决策**：不做兼容层、不渐进迁移——**一步切换**（Mass 新路线正式上位）；旧资产留档供参考

**决策点**：
- **优先级体系生效**：卫星 `Normal` / 玩家 `High`（High 可抢占卫星的 Claimed）——"玩家永远优先"的设计落地
- **玩家操作模型 = 短事务**（认领→执行→同帧释放），与卫星的**长事务**（认领持续整个作业期）形成对照——同一协议两种用法（后续 P6 把卫星也改为"起飞即释放"缩短占用期）
- "未启用 Slot 直接执行"的设计：玩家是"创建者"（耕地/播种会启用 Slot），不参与对空气的认领
