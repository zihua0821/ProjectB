## ② 当时做了什么（功能归纳·当时视角）

```
背景：ISM 管理器被格子（地块/轮廓/作物）三套系统共用，组件创建参数（挂点/阴影/分桶开关）
      由各调用点"随手传"——谁先创建谁定格，且不一致时静默按先到者执行（参数漂移隐患）
本次治理四件事：
  1. 网格参数注册表：每种网格一份参数（单一事实来源），重复注册不一致 → 告警
  2. 参数漂移防御：调用传入与注册值不一致 → 以注册值为准 + 每网格一次性告警
  3. 剔除修复：空桶 → 非空时显式 UpdateBounds（增量 API 不自动更新 Bounds → 视锥剔除失效）
  4. 轮廓两项：轮廓实例接入球面分桶（可剔除）；高亮状态与颜色变更改为互斥分支（修复颜色变化逻辑）
```

## ③ 关键实现与决策点

### 3.1 网格参数注册表（Mesh → Params 单一事实来源）

```cpp
// 新 API：
RegisterMeshParams(Mesh, Params)   // 显式注册（唯一权威）；重复注册不一致 → 告警保留首次
GetMeshParams(Mesh)                // 查询（无锁读；仅游戏线程，checkf 断言）

// 解析规则（ResolveEffectiveParams——所有创建/添加路径统一走它）：
未注册 + 传入非空 → 以传入值"首次定格"（兼容旧调用）
未注册 + 传入为空 → 返回默认（调用方判空→告警"无可用参数"）
已注册            → 一律以注册值为准；传入非空且不一致 → 一次性漂移告警（bParamMismatchWarned 去重）
```
**决策点**：
- **"谁先创建谁定格"改为"显式注册 + 漂移告警"**——把隐式约定显式化（治理而非重构，兼容旧调用）
- 参数等价性比对只关注"影响组件创建的字段"（AttachParent/bDisallowNanite/bCastShadow/bDisableBuckets）——比对范围收窄得当
- 线程约定入代码：写/读均 `checkf(IsInGameThread())`——注释引用《ISMManager 技术文档 §3.3》——文档与代码互锁

### 3.2 剔除修复：空桶 → 非空必须显式 UpdateBounds

```cpp
const bool bWasEmpty = (Group.BucketInstanceCounts[0/BucketIdx] == 0);
Group.TotalInstanceCount += ...;  Group.BucketInstanceCounts[...] += ...;
if (bWasEmpty) { ISMComp->UpdateBounds(); }   // 增量 API 不自动更新——否则视锥剔除失效
```
- 单桶路径与分桶路径**两处同修**（对称处理）——这是"增量 API 不更新 Bounds"这一引擎行为的正式记录（后成为置顶易错点之一）

### 3.3 轮廓两项修复

- **轮廓接入分桶**：CellVisualSyncProcessor 给轮廓实例补 `GridCoords`（与地块分桶同源的格子坐标）——轮廓不再永远单桶，可随视角剔除
- **颜色逻辑修复**：高亮状态变化与颜色变化改为**互斥分支**（`if (bHighlighted变化) {...} else if (bColorChanged) {...}`）+ 同步 `LastHighlightColor`——修复"高亮切换吃掉颜色变更"的状态残留

### 3.4 数量常量收口

- `CellOutlineCustomData::Count = 16`、`CropCustomData::Count` 替代硬编码数字（3）——CustomData 数量从"魔数"变为具名常量；作物调用改为传空 `FISMComponentParams()`（走注册表）

## ⑦ 延伸调查：增量 API 与 Bounds（10-03 补录 · 应“再调查确认原因和边界”）

> UE 5.5.4 源码级调查（InstancedStaticMesh.cpp / ActorComponent.cpp / SceneComponent.cpp）——
> 结论修正了“旧版路径会顺便重算 Bounds”的通俗表述。

**原因（三层机制）**
```
① 写 API 层（同步必然）——AddInstance(s)/AddInstance(s)ById/UpdateInstanceTransform(ById)/
   RemoveInstance(s)ById/SetCustomData 系列全部不内联计算 Bounds；只写 PerInstanceSMData + 标记
   PrimitiveInstanceDataManager 增量脏状态 → 写完立即读 Bounds 必为旧值
② 帧末补偿层（异步·有条件）——组件标脏 → DoDeferredRenderUpdates_Concurrent（ActorComponent
   L1936）→ 非重建分支才走 SendRenderInstanceData_Concurrent → FlushChanges 返回 true
   （有真变更+有代理）→ 【自动 UpdateBounds()】（L2233-2237）。补偿的四个条件（缺一不补）：
   · 同帧 bRenderStateDirty（代理重建，如 SetHiddenInGame 复活）→ 重建分支优先，三个 Send 全跳过；
     CreateSceneProxy（L2280-2313）只 ResetComponentDirtyTracking + Flush(true)——【不含 UpdateBounds】
   · SceneProxy == nullptr → 换分支：UpdateBounds + AddPrimitive（此分支反而正确，L2240-2247）
   · bDetailModeAllowsRendering && (ShouldRender()||…) 不满足 → 整块跳过
   · FlushChanges 无真变更 → false → 不 UpdateBounds
③ 其他自动入口——组件自身 transform 变化 → PropagateTransformUpdate 无条件 UpdateBounds
   （SceneComponent L876-969：移动组件会刷新，移动实例不会）；保守盒机制（bUseConservativeBounds
   默认关；开启且实例数 > GConservativeBoundsThreshold=30 时 UpdateBounds O(1) 用冻结盒）
```
**项目当年现象闭环**：空桶→复活（SetHiddenInGame(false) 触发代理重建）与 Add 同帧 → 踩中“重建分支
跳过补偿” → Bounds 永久零 → 剔除失效（视锥外全剔/视锥内全提交——与 FPS 无提升观测吻合）。
**修复价值确认**：显式 UpdateBounds = 确定性（不依赖帧末时序与分支条件）+ 即时性 + 语义正确（状态转换点）。

**边界表（最终版）**
```
| 场景 | 自动更新 | 说明
| 写后帧内同步读 | 否（必然旧值） | 需要时显式 UpdateBounds
| 帧末·正常分支（非重建+条件满足+有变更） | 是 | 卫星每帧移动走此路径——Bounds 每帧自动刷新
  （O(N)，N 小无碍；即动态实例无陈旧问题，此前理论担忧被引擎补偿层消解）
| 帧末·同帧代理重建 | 否（分支互斥吞掉） | 空桶复活场景 → 已显式修复【高危组合】
| 帧末·代理不存在 | 是（另一分支） | 首实例添加反而安全（UpdateBounds + AddPrimitive）
| 组件自身移动 | 是（无条件） | 移动实例不会触发此路
| 非空桶追加（超出旧盒） | 帧末补偿（有条件） | 项目当前仅空转换点显式；追加依赖补偿（分桶场景影响低）
| 移除实例 | 无显式 | 安全（Bounds 偏大=保守，只损性能不误剔）；归零被隐藏
| Nanite 组件 | 不适用 | Nanite 不依赖组件 Bounds 剔除
```
