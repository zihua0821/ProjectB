## ③ 关键实现与决策点

### 3.1 09f4587：纯实体起步

**Initialize 五步流程**（当时版本，共 117 行）：
```cpp
1. 解析目标轨道定义（ResolveOrbitDefinition：指定名 → 第一个配置 → 兜底默认轨道）
2. 建原型：CreateArchetype（FMassOrbitFragment + FSatelliteTag + 可选 FMassStateTreeInstanceFragment）
3. 批量创建：BatchCreateEntities(Archetype, SatelliteCount, Entities)   // 3 颗
4. 写 fragment：角度均分（i/N×360°）、AngularVelocity、bClockwise、MoveState=Idle
5. 挂 StateTree（ConstSharedFragment 携带资产；实例分配/激活由引擎 Processor 自动完成）
```

**决策点**：
- **手写创建路线**（CreateArchetype + BatchCreateEntities）而非 Mass Spawner——与项目既有的格子创建模式一致（"与格子创建模式一致"注释）→ 演化为后续所有卫星创建链的骨架
- **数据化轨道**：新建 `FOrbitDefinition`（OrbitName/Transform/Radius）放进 `PlanetConfigDataAsset.OrbitDefinitions`——**项目"轨道唯一权威结构"的起点**（终态仍在用，还扩了 ServiceDistance）
- **状态枚举搬家**：`ESatelliteMoveState`（Idle/MovingToTarget/Paused）从旧组件 `OrbitMovementComponent.h` 迁入 Mass 数据层 `SatelliteMassFragments.h`——"数据层统一管理"的第一步；旧组件改为 include 新头（旧系统此时还活着）
- fragment 初版字段：`CurrentAngle` / `TargetAngle` / `MoveState`（还没有后来的 VirtualPhase/State/SlotClaimHandle）
- Build.cs 新增依赖：`MassAIBehavior`、`StateTreeModule`

### 3.2 4c832c8：渲染与移动

**三个新数据/处理单元**：
- `FMassSatelliteSharedFragment`（ConstShared，按值去重）：轨道几何（Transform/Radius）+ 渲染（Mesh/Scale）——**每轨一份共享**的设计从这天开始
- `FSatelliteRenderFragment`：ISM 实例稳定句柄 `FGlobalInstanceId`
- `ComputeOrbitWorldPosition`：**最初写在 Fragments.h 里**（FORCEINLINE 全局函数）——后迁至 BPFL（见 P5）

**两个处理器**：
- `USatelliteOrbitMovementProcessor`：角度推进（Idle 匀速 / MovingToTarget 最短弧走向 TargetAngle，≤0.1° 转 Paused / Paused 停）；纯 fragment 修改→允许并行 chunk；执行组 `SatelliteOrbitMovement`
- `USatelliteRenderSyncProcessor`：读 CurrentAngle → 算世界位置 → 收集 → 末尾一次 `BatchUpdateInstancesTransforms`；**bRequiresGameThreadExecution=true**（ISM 仅游戏线程）+ `ExecuteAfter("SatelliteOrbitMovement")`——**帧序链的起点**（先动后画）

**决策点**：
- 渲染走 **ISM 单桶路径**（`bDisableBuckets=true`——卫星数量少，不需要分桶；与格子/作物的分桶路径区分）
- 运动与渲染**职责分离**：Movement 只改数据可并行；RenderSync 独占游戏线程——这套"数据推进 / 表现同步"分层沿用至今

### 3.3 1d07bab：第一版任务闭环（重点）

**`SatelliteTaskProcessor`（163 行，次日即被重构删除）**——全部任务逻辑写在一个处理器的 `switch (Task.TaskState)` 里：

```cpp
// 巡航态 TryAcquireTarget：
1. 卫星世界位置 → 球面反推"最近格子"（ConvertLocationToCellCoord）
2. 读该格 CropStateFragment：不是 Mature 就跳过
3. 【选点后立即认领】TryClaimSlot(coords, CropSlot=1, Normal) —— 移动前占位防抢
4. 算目标角度（CalculateOrbitAngleFromCell）→ 置 TaskState=MovingToTarget + MoveState=MovingToTarget
// 前往态 TryExecuteTask：
到达检测 = MoveState==Paused（移动处理器置位）
→ 执行收获（复用玩家入口 HandleLeftMouseClicked(HarvestCrop)）
→ 释放认领 → 清目标 → 回巡航
```

**决策点（含隐患）**：
- **移动前认领**：从第一版就确立了"选点即认领"的核心不变量（多星不同抢）——沿用至今（注：终态把释放时机从"执行后"改到了"回轨起飞"，见 P6）
- **执行复用玩家入口**：AI 与玩家走同一操作函数——单一操作实现（终态演化为 `ExecuteFarmAction`）
- **帧序链扩展**：`SatelliteTask` 执行组 + Movement `ExecuteAfter("SatelliteTask")` → 链：**Task → Movement → Render**（终态扩展为 Plan → Slots → Movement → Render，P7）
- ⚠️ **双状态枚举埋雷**：`ESatelliteMoveState`（移动三态）与 `ESatelliteTaskState`（任务两态）并行存在、互相耦合读写（如"到达=MoveState==Paused"）——**"双字段不同步"隐患的源头**（终态在 P6 合并为单一 `ESatelliteState` 六状态）
- 选点方式为"**最近格子反推**"——卫星只能发现正下方格子；覆盖带扫描、活跃农田集合要等 P2/P3

**同时期的两处作物修复（保留至今）**：
- `CropOffset` 改为**格子局部坐标系**转换：`TransformVectorNoScale(CropOffset)`——含旋转格子的作物偏移不再错位（CropManager + CropVisualSync 两处同修）
- 作物生长条件从"读作物自身 NeedsWater/NeedsFertilizer"改为"读地块 Watered/Fertilized 状态"——判据与地块状态同源（CropGrowthProcessor）
- 新增 `PresetMatureCropPlots`（测试预置：赤道行整排成熟作物）——卫星收获的演示/测试设施（保留至今）
