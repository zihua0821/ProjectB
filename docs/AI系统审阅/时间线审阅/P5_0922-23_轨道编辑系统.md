## ③ 关键实现与决策点

### 3.1 运行时轨道数据体系（编辑系统的数据地基）

```
FRuntimeOrbitData : public FOrbitDefinition   // 几何继承权威结构；运行时字段独立
  + SatelliteCount / AngularVelocity / bClockwise     // 该轨卫星参数
  + VisualColor / CoverageColor                        // 颜色（面板可改）

编辑接口五件（SatelliteManager）：
  UpdateOrbitData（按名定位 + 改名保护 + 广播）        // 仅数据与可视化；不重建
  AddOrbit（重名防护 + 兜底服务距离 + 重建 + 广播）
  RemoveOrbit（移除 + 重建 + 广播）
  ApplyOrbitChanges = DestroyAllSatellites + CreateAllSatellites   // 全量重建
  OnRuntimeOrbitChanged 广播 → 可视化组件订阅（节流刷新）

CreateAllSatellites：逐轨 CreateSatellitesForOrbit（每条轨道一份 ConstShared）→ 统一 RegisterRenderInstances
```
**决策点**：
- **"数据（RuntimeOrbits）— 表现（可视化广播）— 运行体（卫星实体重建）"三层解耦**：改参数=只动数据+刷新可视化；点"应用"=重建卫星。实时预览不重建（拖动流畅），重建显式触发——P8 的"实时应用（提交即重建）"正是把这两步合并
- 运行时数据**继承**权威结构（几何字段唯一来源仍是 FOrbitDefinition）——避免双定义漂移
- **ApplyOrbitChanges 全量重建**（简单直接；轨道少时够用）——**代价在 P8 暴露**（任意编辑全轨重建 → 改为按轨重建）

### 3.2 覆盖判定换代：半格高 → 平面带 + ServiceDistance（覆盖模型第 2 代，定稿）

```cpp
// BPFL 新增（4805a47）：
ComputeOrbitWorldPosition   // 从 SatelliteMassFragments.h 迁入（P1 报告标注的迁移在此确认）
ComputeDistanceToOrbitPlane // 点到平面垂直距离
IsPointInOrbitCoverage      // 平面带：距离 ≤ ServiceDistance
// 头文件注释定调："选点系统 / 可视化 / 编辑预览共用此判定（唯一权威）"

// 同时 BPFL 清理：GetNearestCellCoordFromOrbitAngle 删除（旧"最近格子"最后遗物）
// FOrbitData → FOrbitDefinition 全量替换（签名统一到权威结构）
```
**决策点**：
- **覆盖模型从"半格高系数"（P3）改为独立 `ServiceDistance`**——覆盖带厚度成为**可独立编辑的业务参数**（不再绑定格子物理尺寸）；P3 的 `CoverageHalfThicknessScale` 系由此退役
- **旧物理覆盖集正式退役**（OrbitManagerComponent 重构）：删除 `OverlapMultiByObjectType` 覆盖查询 + `CoveredCoordsMap` 维护 + CellManager 依赖——"几何判定 + ISM 化可视化"取代"物理 Overlap + 调试圆"
- 注：**"管∩球面"的措辞**自旧系统沿用（OrbitManagerComponent 注释），与"平面带"实现并存——就是前导发现 **B2** 的注释矛盾源头（本阶段写下，P7 实际验证为平面带语义）

### 3.3 可视化组件：零程序化几何（`OrbitCoverageVisualComponent`）

```
每轨道：轨道圆环（N 段引擎网格沿切线拼圆）+ 服务范围圆柱（引擎 Cylinder 缩放；半高 = 服务距离）
渲染：统一经 ISMManager 单桶路径；颜色经实例 CustomData（RGBA）传递
覆盖格高亮：复用轮廓高亮层（FHighlightFragment；增删 diff，批量标记）
刷新节流：数据变化置脏 → Tick 按 RebuildInterval 重建（拖动友好）
```
**决策点**：
- **"零程序化几何"**（只用引擎 BasicShapes 网格 + 实例变换）——免自定义 SceneProxy/免编译期几何代码，编辑时只更新 Transform——工程务实
- 覆盖格高亮**复用格子轮廓层**（不新造高亮通道）——"覆盖的权威表达"是格子高亮 diff，与悬停高亮共用 `FHighlightFragment`

### 3.4 编辑面板与 PC 接口（初版全貌）

```
SOrbitEditorPanel（初版）：轨道列表（增/删/选）+ 参数（Center 三轴 / Tilt 倾角 / Azimuth 方位 / Radius /
  ServiceDistance / SatelliteCount / AngularVelocity / Clockwise / 颜色[调色板+取色]）+ 按钮（Add/Delete/Apply/Close）
数据流：WorkingData（编辑副本）→ PushWorkingDataToManager（实时预览）→ SetOrbitData（PC 转发接口）
PC 接口层：GetOrbitNames / GetOrbitData / SetOrbitData / CreateOrbit / DeleteOrbit /
  ApplyOrbitChangesToSatellites + Exec 命令（OrbitSetServiceDistance/Radius/Center/Normal + OrbitShowEditor）
编辑模式：EnterOrbitEditMode = 可视化为开 + 悬停高亮互斥；Exit = 关可视化
```
- **面板与逻辑解耦**：面板经 PC 接口转发（不直接摸 Manager）——P8 的 friend 白名单/接口收窄沿用此结构
- Exec 命令保留了"改第一轨"的快速调试通道（终态仍在）

### 3.5 高亮路径修复：Defer → 同步直写（双路径竞态）

```cpp
// UpdateOutline（CellManager）从 Defer 延迟写 → 同步直写 FHighlightFragment
// 注释："统一写路径（与覆盖格高亮同款）；不可用 Defer——延迟写会在帧末覆盖后续同步写入的覆盖色
//       （悬停/覆盖双路径时序竞态）"
```
- 覆盖格高亮（编辑模式）与悬停高亮（正常模式）**共用轮廓层**——两者写同一 fragment，Defer 延迟写会造成"帧末覆盖"，改为同步直写统一时序——**"写入路径必须同源"的实操教训**（后成为易错点体系一员）
