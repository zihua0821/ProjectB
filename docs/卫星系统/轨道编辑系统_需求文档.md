# 轨道编辑系统_需求文档

> 玩家功能：编辑卫星轨道 → 实时看到覆盖范围（球面投影 + 覆盖格高亮）→ 规划种植布局。
> 与农业闭环衔接：**覆盖范围 = 卫星的服务区**，编辑轨道即调整服务区。
> 本文档为需求层定稿基线；设计与实施计划另见后续文档。

---

## 一、背景与目标

**现状**：卫星在固定轨道上运行；轨道定义在配置资产中（不可运行时编辑）；覆盖范围无任何可视化。

**目标**：
1. 玩家可在游戏内**编辑轨道参数**（数值面板），实时看到覆盖范围变化
2. 覆盖范围有**可视化表达**（空间中的轨道 + 球面上的投影区）
3. 覆盖格子有**视觉反馈**（复用现有轮廓高亮层，批量 + 分桶渲染）

---

## 二、核心模型（权威定义）

### 2.1 轨道定义

```
轨道圆：圆心 C、平面法线 N、半径 r
   - C 可任意偏移（不要求经过球心）——本项目明确的编辑自由度
   - 卫星沿该圆运动（方向由角速度/顺逆时针决定）

服务半径：s（可编辑的"覆盖宽度"，即轨道"管"的半径）
```

### 2.2 覆盖判定（管 ∩ 球面）

```
把轨道视为一个"管"：中线 = 轨道圆，管半径 = s
覆盖区 = 管 ∩ 球面 = 球面上「到轨道圆的距离 ≤ s」的点集

判定公式（每个格子 O(1)，多次向量运算）：
  axial  = dot(P − C, N)                    // P = 格子中心（球面点）
  radial = |(P − C) − axial·N|              // 面内分量
  dist   = sqrt((radial − r)² + axial²)      // 到轨道圆的真实空间距离
  覆盖 ⟺ dist ≤ s
```

**说明**：
- 该定义是"卫星轨迹正下方 ± 服务半径"的严格几何表达（管 ∩ 球面）
- 轨道过球心（C=0，d=0）时，与旧"平面带"判定在行为上一致（向后兼容）
- **判定唯一权威**：选点系统（卫星）/ 可视化 / 编辑预览共用同一函数，杜绝三处不一致

### 2.3 边界情况（编辑时可直接观察到）

```
管与球不相交（轨道太远）    → 无覆盖（空）
管与球相切                   → 覆盖区收缩为一条线
s 增大                       → 覆盖带变宽（可编辑，用户已确认）
```

## 三、功能需求

### FR-1 轨道本身可视化

```
表达：完整圆圈（闭合）——卫星飞行轨迹
技术：环带 Mesh（程序化生成，参数化宽度/分段）+ 材质
      （粗细可控——避免线段粗细不可控的问题）
可选增强：流动/发光材质表现卫星方向
```

### FR-2 覆盖范围可视化（两块独立内容）

```
① 轨道范围（空间中的"管/圈"）
   - 表达：轨道圆 + 管范围（圆柱/双圈示意）
   - 使用真实宽度（极窄也接受——用户确认）

② 球面投影（球面上的覆盖带）★ 重点
   - 需求："把完整的投影画到球面上"（连续区域，非只有两条线）
   - **技术选型（已定）：程序化球面环带 Mesh（DynamicMesh 路线 β）**
       技术基础：`UDynamicMeshComponent`（引擎 Runtime 基础模块 GeometryFramework——
                 非插件，零 uproject 依赖；Build.cs 加 GeometryFramework/GeometryCore）
       生成：沿轨道角度采样 → 每 θ 在截面平面内解 2D 两圆交点
             → 得带的上下边界（+ 可选中线做顶点色渐变）
       更新：参数变化 → EditMesh 重建顶点（256 顶点级，轻量可节流）
       理由：贴合"系统方向"（操作网格数据结构，渲染细节交引擎）；
             窄带场景渲染面积最小；与 ISM 静态批量经验形成"数据管线"叙事
   - 已排除方案：
       材质球壳（渲染开销与带宽无关，窄带浪费）
       后处理材质（全屏固定成本 + 遮挡顺序问题）
       自建 FPrimitiveSceneProxy（渲染向，与系统方向不符）
```

### FR-3 覆盖格高亮（复用现有轮廓层）

```
需求：被覆盖的格子显示高亮（离散表达的"投影"）
复用：现有轮廓高亮层（FHighlightFragment + OutlineMesh + M_CellOutline）
      —— 独立 ISM 通道，与地块渲染（LandCellMesh）无关

★ 现状评估（2026-09-19 调研）：
  ├─ 批量：✅ 已支持
  │    CellVisualSyncProcessor 三处均为批量：
  │    BatchRemoveInstances / BatchAddInstances / BatchUpdateInstanceCustomData
  ├─ 分桶：❌ 未支持（单桶路径）
  │    CellVisualSyncProcessor.cpp L144：BatchAddInstances(..., {}, /* S1 轮廓：单桶 */, ...)
  │    单桶后果：几百~千个覆盖格高亮时，整桶无剔除（包围盒=全星球，背面实例也提交）
  └─ 结论：需要改造（见下）

改造需求：
  1. 轮廓实例走球面分桶（BatchAddInstances 传入格子 GridCoords——与地块分桶同源）
  2. 高亮集合变化采用增量 diff（编辑轨道拖动时覆盖集平滑变化——
     仅增删差异实例，避免全量重建）
  3. 保持批量接口（沿用 ISMManager 现有 Batch* 系列）
```

### FR-4 轨道编辑（玩家功能）

```
入口：游戏内 UMG 数值面板（本期不做视口拖拽手柄）
参数（全参数可编辑）：
  ├─ 圆心 C（偏移——不经过球心）
  ├─ 平面法线 N（倾角 / 方位）
  ├─ 轨道半径 r
  └─ 服务半径 s（覆盖宽度）
多轨道：支持新建 / 删除轨道
联动：参数变化 → 覆盖重算 → 可视化刷新（FR-2/FR-3）
      （选点系统使用同一覆盖判定——见 2.2"唯一权威"）
   
待定（本期可选项）：
  - 卫星数量 / 角速度 / 顺逆时针 是否纳入面板（或继续留在组件配置）
```

### FR-5 高亮互斥规则

```
进入轨道编辑模式时：
  ├─ 悬停高亮关闭（不触发 UpdateOutline）
  └─ 覆盖格高亮启用（独占轮廓层——两者互斥，无叠加问题）
退出编辑模式：恢复常规悬停高亮
```

## 四、非功能需求

| 项 | 要求 |
|---|---|
| 性能-渲染 | 覆盖格高亮分桶后可剔除；实例数按覆盖带规模（预期几百~千）评估 |
| 性能-更新 | 编辑实时变化 → 增量 diff + 批量接口；避免逐实例调用 |
| 一致性 | 覆盖判定唯一权威函数（选点/可视化/编辑共用） |
| 可调试 | 保留调试绘制路径（轨道圆/边界/覆盖格框 + 控制台开关）——开发期快速验证 |

## 六、验收标准

```
场景 1（基础显示）：开启可视化 → 看到轨道圆 + 球面覆盖带 + 覆盖格高亮
场景 2（偏移编辑）：拖动圆心/法线 → 覆盖带跟随移动（与判定公式一致）
场景 3（服务半径）：拖动 s → 带宽变化；s 极小时收缩为细带；不相交时为空
场景 4（多轨道）：新建第二条轨道 → 两条覆盖带并存、互不干扰
场景 5（互斥）：进入编辑模式 → 悬停高亮消失、覆盖高亮独占
场景 6（性能）：覆盖带数百格高亮时帧率稳定；分桶剔除生效（背面不提交）
场景 7（一致性）：卫星选点命中的格子 ⊂ 高亮显示的覆盖格（判定一致）
```

## 七、已确认决策（v1.2）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 编辑后卫星更新机制 | **A**：拖动实时更新可视化（圆/带/高亮）；点"应用"后重建卫星实体 |
| 2 | 编辑模式入口 | **B**：独立"轨道编辑模式"（进入时触发悬停高亮互斥） |
| 3 | 服务半径归属 | **A**：作为**轨道参数**（每条轨道一个 s；S = 管半径 = 覆盖宽度） |
| 4 | 多轨道卫星安排 | **A**：每条轨道可配卫星数量（面板可调） |
| 5 | 材质资源分工 | **A**：本项目出材质参数规格说明，用户在编辑器配 MI |

**默认值（工作区可调）**：

```
覆盖带抬升   ：贴地表格子表面上方（与格子高亮对齐）
高亮颜色     ：覆盖带=青色系 / 覆盖格高亮=金色系（与悬停色区分）
滑块范围     ：r ∈ [0.2R, 5R]；s ∈ [0.1, 3] × 格子高；圆心偏移 ∈ [−R, R]
拖动节流     ：可视化 30Hz；高亮 diff 每帧合并
判定替换     ：选点同步切"管∩球"（C=0 时与现状等价，行为不变）
存档         ：本期不做（编辑结果不持久化）
```

## 附：模型修订说明（v1.3，最新权威）

> 本节覆盖前文 2.2 / FR-2 中的旧描述（"管 ∩ 球面"判定与"球面连续形状"渲染均已废弃）。

**覆盖判定（平面带）**：

```
覆盖区 = 球面上「到轨道平面的垂直距离 ≤ 服务半径 s」的点集
判定：dist = |dot(P − C, N)| ≤ s      （P=格子中心球面点；C/N=轨道圆心/法线）
与轨道半径无关（轨道半径只影响卫星飞行位置与奔赴距离）
```

**服务距离（原名"服务半径"，v1.5 统一命名）**：覆盖带半厚（覆盖"圆柱体"的半高）；默认 = 半格高；编辑面板可调。

**轨道定义（v1.5 统一）**：项目唯一权威结构 = `FOrbitDefinition`（名称 / Transform / 半径 / 服务距离）；
运行时扩展 `FRuntimeOrbitData` 继承之；旧结构 `FOrbitData` 已删除（含旧物理覆盖集）。
Transform 三自由度语义：Roll=方位 / Pitch=倾角 / **Yaw=相位零点（轨道起点）**。

**可视化（三件表达）**：

```
① 轨道圆环：表达轨道面（程序化细环带，双面）
② 服务范围圆柱：半透明侧壁，半径 = max(轨道半径, 星球半径×系数)、半高 = s
   —— "板"的立体表达；圆柱与球面的交线即覆盖带边界（几何自洽）
③ 覆盖格金色高亮：覆盖的权威表达（复用现有轮廓层，离散且语义准确）
```

**废弃项**：球面覆盖带 Mesh（BuildSphereBand）已删除；"r±s 同心双圈"已删除。
