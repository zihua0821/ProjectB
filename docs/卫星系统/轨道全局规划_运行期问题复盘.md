## 二、关键问题详录（5 例）

### 2.1 "陷入整理"与"推挤循环"（#3 + #4）

```
现象：运行一段时间后所有卫星持续微调（move≈±1 格），工作荒废；
      后期漂移/作业比从 1.3:1 崩到 4.5:1
根因链：
  ① 触发条件用【全体占位】判定，但求解只能动【可动星】
     → 不达标源在不可动星（在途/待返）上时，触发条件永真
  ② 求解对"其实已达标"的星仍产出 ±1 格伪位移（目标位→最近空槽不含自身位）
  ③ 前移优先（P2）让"把挤推给前邻"优先于"后移吸收" → 挤波绕环滚动（贪吃蛇）
  ④ 相邻间距恰在线值时（离散网格 4 格 = 0.8 线），浮点误差让"贴线"永远欠一丝
修复：
  · 求解目标收敛为"消除过近"：与最近邻居 ≥ 有效线 → 免动；只动挤对中可动的一方
  · 后移保底绝对速度（0.25ω）消除"停住"；前移优先消除"相向穿越"
  · 阶段② 5s 独立节流（决策节拍与漂移时长匹配）
效果：工作前后段 122/119（稳态）；漂移稳定在 50+/轮（必要的回轨让位，不累积）
```

### 2.2 条件转移竞态 → 中断卡死（#8）

```
现象：漂移中断后部分星"消失"——不作业、不再漂移；延迟送达 36s（≈1 圈）/180s（≈5 圈）
根因：
  中断发生在【任务阶段】（认领 → 返回 Succeeded）
  转移条件读的是【评估阶段】刷新的评估器数据（那时还没认领 → false）
  "能否等到'评估器刷到 true 的那次执行'"取决于 Mass 补 Tick(0) 与状态树执行序
  → 跨子系统竞态（实测成功率 50%）→ 直切失败 → 回 Cruise 重新选点
  → 本格已被自己认领（跳过）→ 等窗口 → 长真空
本质：任务的【瞬时完成意图】被要求跨帧、跨节点（评估器）传递——架构错配
根治（R-B）：取消"条件区分"——Drift 成功统一 → Depart；
  滑完（无认领）→ DepartWait 首帧"无目标"Failed → 回 Cruise（1~2 帧自愈）
  + X 复用分支（已有有效认领 → 直接 Succeeded）兜底一切异常回访
效果：中断送达 4/4 全部 13~19ms；reuse 兜底 0 次触发
```

### 2.3 累积角 × FindDeltaAngleDegrees（#6）

```
现象：漂移 move=352.8°（应为 -7.2°）→ 22 倍轨道速度绕圈、穿透群星
根因：FindDeltaAngleDegrees 只做一次 ±360 修正（要求输入差 ≤±540°）；
      槽相位/虚拟相位是持续累积量（运行约 2 圈后 >720°），与反算归一角相减
      原始差可达 700°+ → 单次修正不足 → 输出 360 倍数偏移值
      且规划器/防撞用"同源差"（算对）、执行层算成大弧 → "判据与执行不同源"放大
修复：跨源角差一律先归一（mod 360）再求差（漂移 Δs / 回轨 δ0 / 选点行程 / 规划等待角 四处）
教训：凡"长期累积相位"与"atan2 类反算角"求差，必须先归一
```

### 2.4 幽灵认领黑洞（#7）

```
现象：部分星/全场反复"掠过工作地块"却不干活
根因：探测即认领的认领依赖"后续流程送达"；一旦中断未送达 → 认领悬挂（幽灵）
      扫描/评分不检查认领状态 → 被占格（有缺口、分高）成为"黑洞吸引子"
      每颗星被吸引 → TryClaim 失败 → 整单放弃 → 本轮谁都接不了活
修复：R1 扫描跳过"已被任何人认领"的格子（黑洞隔离 + 最高分自动顺延）
      R2 认领失败告警（区分幽灵 vs 瞬时竞争）
```

### 2.5 跨驱动源时序 → 规划器搬迁（#11）

```
现象：抄账时点不确定（组件 Tick 与 Mass 帧序先后未约定）；槽推进与渲染同步错位
根因：三个驱动源（组件 Tick / Mass 处理器 / 状态树）碰同一批数据，相对顺序无约定
修复：所有"运行时驱动"收编进 Mass 帧序——
  USatelliteOrbitPlanProcessor（规划）→ SatelliteOrbitMovementProcessor（槽推进→卫星推进）
  → SatelliteRenderSyncProcessor（渲染同步）→ 心跳 → 状态树
  组件 Tick 退出运行时驱动（仅保留注册期职责）
```

## 三、架构收敛（本轮最终形态）

```
四个体系，职责边界清晰：
· 瞬时事实（"刚认领了"）→ 只走【任务内部】，不跨帧表达（R-B 教训）
· 跨帧状态（状态/相位/句柄/认领）→ 走【fragment】（单一事实源）
· 全局决策（群体规划）→ 走【Mass 帧序】的确定时点（规划处理器）
· 长期状态编排 → 只留给【StateTree 的状态】（评估器退回纯数据源）

Mass 帧序（显式声明）：
  规划 → 槽推进 → 卫星相位推进 → 渲染同步 →（心跳）→ 状态树任务
```

## 四、方法论沉淀

1. **瞬时事实不跨帧表达**：任务的完成意图/瞬时事件绝不用"评估器 + 条件转移"跨帧传递（竞态温床）
2. **判据同源**：触发线/免动线/合规线、Depart 判据、任务侧与规划器公式——同一口径、同一常量、同归一化
3. **离散网格边界**：触发线在离散槽网格上有"不可满足/贴线"区间（0.95 永动；20 星 0.8 贴 4 格）——取值需数学验算
4. **驱动源统一**：跨子系统碰数据前，先在"一个帧序"内约定相对位置
5. **探针方法论**：断点不可信（Mass StateTree）→ 变化驱动日志 + 定向探针（送达/等待/吞格）一步定位
6. **兜底 vs 根治**：条件转移竞态 50% 成功率——修"竞态"不如删"环节"（R-B 把最脆的链路整个移除）
7. **观测闭环**：每个修复配"可验证的指纹"（日志计数对比：送达率/前后段 work 比/漂移比）
