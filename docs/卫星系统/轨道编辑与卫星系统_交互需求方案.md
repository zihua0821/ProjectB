# 轨道编辑与卫星系统 · 交互需求方案（v1.1 定稿）

> **状态**：**v1.1 —— 定稿 · 已实施**（2026-10-01；实施完成与实施记录见《轨道编辑与卫星系统_执行方案.md》第七节）　**分支**：`MassCrop`
> **定位**：定义「轨道编辑系统」与「卫星系统」的交互契约；代码修复（已审查出的 P0/P1）作为契约的实现落地
> **背景**：耐力回归 R4 实测发现两系统交互存在冲突（不限于重建时序类），代码审查确认三类结构性缺口
> **设计依据（已确认）**：游戏类型 = 放置向自动化农场——编辑交互的本质是"管理面板"；
> 暂停模拟对放置玩法几乎无损，且能一举消除"编辑 × 运行时并发"的整类冲突

---

## 一、背景与问题域

### 1.1 两个系统的职责定位

```
轨道编辑系统（Widget + PlayerController + OrbitManager）：
  配置意图的【表达与预览】——编辑态 = 工作数据（WorkingData）
卫星系统（SatelliteManager + Mass 实体 + 槽位 + 规划器）：
  运行时行为的【执行】——运行态 = 实体数据（fragment / 认领 / 槽位）
```

### 1.2 现状交互链路（实读代码确认）

```
【编辑层】
· 参数修改（半径/圆心/法向/服务距离）→ UpdateOrbitData → 只写 RuntimeOrbits + 广播可视化
  → 【不重建】——卫星仍按旧参数运行（"编辑-生效分离"事实上已存在于参数路径）
· 新建轨道 → AddOrbit →【内部直接 ApplyOrbitChanges（立即重建）】
· 删除轨道 → RemoveOrbit →【内部直接 ApplyOrbitChanges（立即重建）】
· Apply 按钮 → ApplyOrbitChangesToSatellites → ApplyOrbitChanges（重建）

【重建层】ApplyOrbitChanges：
  ① RegisterOrbitSlots（Reset 旧表 → 全部新建槽位）
  ② DestroyAllSatellites（移除 ISM 实例 + 销毁实体）
  ③ CreateAllSatellites（批量建实体 + 初始槽认领 i×K）
```

### 1.3 已确认的三类结构性缺口（代码审查）

| 编号 | 缺口 | 级别 | 后果 |
|---|---|---|---|
| G-A | **销毁卫星不归还格子认领**（DestroyAllSatellites 零 ReleaseClaim；引擎层 slot 永久 Claimed + 账本残留） | **P0** | 编辑后该格永久不可用（选点跳过 + 认领必失败）——"编辑后农田局部死寂" |
| G-B | 销毁卫星不归还轨道槽认领；旧 SO 槽实例不销毁（RegisterOrbitSlots 仅 Reset 本组件表） | **P1** | 槽实例随每次编辑堆积（R2 里编辑 6 次）；子系统脏数据 |
| G-C | 重建后初始槽认领失败静默（无日志/重试） | **P0 半** | 无槽星不可见（渲染回退账面相位、行为漂移） |

## 二、核心交互原则（全部已确认；实施完成）

```
P1【暂停编辑 + 实时应用】（v1.1 修订：全局暂停 → 选定暂停）
   进编辑模式 = 选定暂停（独立暂停系统：仅暂停"世界演化"链——心跳/规划/运动/作物生长；
      玩家自由飞行/相机、编辑可视化（高亮/悬停）、UI、渲染同步均不受影响）
   编辑期间 = 所有改动【实时应用】（所见即所得）：
      · 参数/结构变化 → 修改运行时数据 + 触发重建 → 卫星/槽位/轨道线即时呈现新效果
      · 【无 Apply 按钮】——所有变化实时反馈可见（触发节奏：提交落定——回车/失焦）
   退出编辑模式 = 应用未落地改动（如有）→ 恢复运行（开始/继续模拟）
   · 收益：暂停排除并发 → "实时重建"安全；所见即所得 → 编辑效率与掌控感最好
   · 落点：EnterOrbitEditMode / ExitOrbitEditMode → 调用暂停系统（SetSimulationPaused）

P2【归还原则】
   卫星销毁前必须归还一切认领（格子全量句柄 + 轨道槽句柄）——由卫星系统主动执行
   · 资源生命周期规则：认领是"借"，销毁前必"还"；不得依赖引擎兜底

P3【重建事务性】
   退出编辑的重建 = "清理 → 销毁 → 重建"的原子序列（同帧完成）；任一步失败必须【可见】（告警）且不留半态
   （暂停不替代本纪律——重建若仍有泄漏，第 N 次进出编辑就会累积）

P4【无槽星不应存在（可见性约束）】
   · 结构保证：卫星与其轨道的槽位在【同一次重建】中同生（槽全新建 → 星认领新槽）——
     认领无竞争、必然成功；无槽星不是"待处理状态"，而是"重建不完整"的异常信号
   · 唯一失败路径：槽注册不完整（引擎创建/捕获失败——已有 Warning）
   · 处理：认领失败必须【可见】（Warning）；不设"运行期补齐"机制（不需要）

P5【槽位实例生命周期】
   旧槽实例由 SmartObjectManager 统一销毁（DestroySmartObject），不依赖引擎/World 生命周期兜底
```

## 三、场景定义（逐场景的预期行为）

| 场景 | 现状行为 | 目标行为（v1.1——已实施） |
|---|---|---|
| S1 编辑改参 | 不重建（卫星按旧参跑） | **实时重建**——卫星/槽位即时跳到新参数下的构型（所见即所得） |
| S2 新建轨 | **立即重建**（语义不一致） | **实时重建**（新轨+卫星+槽位即时出现）——与 S1 语义统一 |
| S3 删除轨 | **立即重建** | **实时重建**（该轨星销毁并归还一切认领）——与 S1 语义统一 |
| S4 编辑中不退出 | 模拟照跑（星在旧参上干活） | **保持暂停**（世界冻结；随时观察每次改动效果） |
| S5 **退出重建时"有星在作业/待回/在途"** | 星被销毁——**认领泄漏**（G-A） | **暂停时全部冻结**（无"进行中"动作）；重建时：<br>□ 格子认领归还（作物状态不动）<br>□ 轨道槽认领归还 □ 旧槽实例销毁 □ 新星全部正常认领（无槽星 = 0） |
| S6 连续编辑 N 次 | 每次泄漏 / 实例堆积 | 无任何累积（每次进出编辑 = 一次干净重建） |

## 四、职责划分（草案）

| 动作 | 编辑系统 | 卫星系统 | SmartObjectManager |
|---|---|---|---|
| 编辑数据（工作数据持有） | ✓ | — | — |
| 写运行时轨道数据 | 发起 | ✓（UpdateOrbitData / Add / Remove） | — |
| **实时应用的触发**（编辑期间每次改动） | ✓（面板发起） | ✓（修改数据 + 重建） | ✓（重建槽位） |
| 重建槽位（清旧实例 → 建新） | — | ✓（调用方） | ✓（实现方） |
| **销毁旧星 = 销毁 + 归还认领** | — | ✓（按轨销毁链 DestroySatellitesForOrbit 负责归还） | ✓（提供 ReleaseClaim / DestroySmartObject） |
| 重建新星（含初始认领） | — | ✓ | — |
| 暂停 / 恢复（进/出编辑模式） | ✓（发起） | — | — |
| 失败可见性（告警） | — | ✓ | ✓ |

## 五、决策记录（全部已确认）

```
1. 选定暂停（独立暂停系统 USimulationControlSubsystem）：进编辑/退出恢复；
   仅停"世界演化"链（心跳/规划/运动/作物生长）——玩家控制（自由飞行/相机）与
   编辑相关可视化（高亮/悬停）保持运行；子系统只持状态（白名单 = 各处理器自检行）✓
2. 实时应用的触发节奏：b) 回车/失焦【提交时应用】✓
   （键入/滚轮/箭头过程中：数据 + 可视化更新；提交落定 → 触发重建）
3. 无槽星：不应存在（同次重建结构保证）——不设补齐机制；认领失败 = Warning 可见 ✓
```

## 六、验收标准（契约成立即代码修复的验收）

```
① 编辑 N 次（含 Apply 时星在作业/待回/在途）后：
   · 格子认领无残留（IsSlotClaimed 全清、引擎 slot 可再认领）
   · 槽实例不堆积（旧实例被显式销毁）
   · 无槽星 = 0（同次重建结构保证）；claim failed = 0
② 各场景行为符合第三节定义（S1~S6）
③ 编辑交互与 P1 一致：进编辑=暂停、编辑=实时可见、退出=恢复运行（无 Apply 按钮、无"意外立即执行"）
```
