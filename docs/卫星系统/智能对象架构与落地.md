> 本文档为 ProjectB 智能对象体系的架构定稿：三层分工、资产定义、双 Slot 架构、Slot 级锁语义、行为落实到实际操作的链路、MassSignals 通知生态位、操作层不重写的决策。
> 状态：**定稿**（2026-09-02）。配套文档：同目录《Mass AI重构计划.md》《Mass AI模块调研.md》《Mass AI迁移与智能对象接入调研.md》。

## 一、总览：三层分工架构（核心准则）

操作逻辑分三层，各司其职，**不要混层**：

```
触发层（仲裁谁操作）          执行层（命令式改状态）           通知层（状态广播）
玩家点击 ──┐                                                    │
           ├─→ CellManager 操作函数 ──→ 状态变更 ──→ MassSignals
卫星（经   │    （校验/改 fragment，      （fragment）            │
智能对象锁）┘     保留现有命令式）                               ↓
                                                       订阅者响应：
                                                       能量/UI/动画/Slot启停
```

| 层 | 机制 | 职责 | 决策 |
|---|---|---|---|
| **触发层** | 智能对象锁（Slot 认领） | 仲裁"谁在什么时候操作哪个格子" | 新增（阶段 3+） |
| **执行层** | `CellManager` 命令式函数 | 校验 + 修改 fragment（现有代码） | **保留，不重写** |
| **通知层** | `UMassSignalSubsystem` | 状态变化后的广播通知 | 新增（阶段 5+） |

**核心原则**：并发控制在上层（锁），状态修改在执行层（命令式），事件广播在通知层（信号）——每层用自己擅长的机制。

## 二、智能对象是什么（心智模型）

> 智能对象 = "可交互点位的声明 + 认领/占用仲裁"。本体是 `USmartObjectDefinition` 蓝图资产，运行时由 `USmartObjectSubsystem` 管理实例。

完整流程 4 阶段（本项目采用 B 路径选点，见第六章）：
```
① 资产定义（蓝图资产：点位+行为） → ② 实例注册（CreateSmartObject）
   → ③ 选点（自研状态查询，非引擎 FindSmartObjects） → ④ 认领→使用→释放（Slot 级锁）
```

## 三、资产定义（USmartObjectDefinition）

### 3.1 资产是"一类交互点模板"，非"一个对象"

- 资产 = "Sharable information"（源码注释），**多实例共享一份资产**
- 6 万格子 ≠ 6 万资产 = **一份资产 + N 次 `CreateSmartObject` 实例化**（每实例带坐标荷载）

### 3.2 资产内两级结构

| 级 | 字段 | 用途 |
|---|---|---|
| 资产级 | `ActivityTags` / `UserTagFilter` / `Preconditions` / `DefaultBehaviorDefinitions` | 整体匹配过滤 |
| Slot 级 | `Offset` / `Shape` / `ActivityTags` / `BehaviorDefinitions[]` / `DefinitionData[]` | 点位定义 + 行为挂载 + 数据荷载 |

### 3.3 行为定义是"参数包 + 类型标签"，不执行逻辑

执行者是使用方框架（Mass 或 GameplayInteractions），通过读行为定义决定"怎么做"。

## 四、资产组织架构（定稿：双 Slot）

### 4.1 项目语义：地块与农作物是两个独立实体

- `FPlotStateFragment`（地块状态）与 `FCropStateFragment`（作物状态）本就是分离的
- 操作按对象分类：灌溉/施肥 → 地块；收获 → 作物；除草 → 两者

### 4.2 定稿方案：双 Slot（B 路径版：不配 ActivityTags）

```
DA_FarmCell（USmartObjectDefinition）
├── ActivityTags: （留空——B 路径不走引擎查询，无需 Tag；Validate 不检查）
├── Slot[0] "Plot"（地块）
│   ├── BehaviorDefinitions: UFarmIrrigationBehavior / UFarmFertilizeBehavior / UFarmPlowBehavior / UFarmPlantBehavior / UFarmWeedingBehavior
│   └── 初始 bEnabled: false（未耕地默认禁用）
├── Slot[1] "Crop"（农作物）
│   ├── BehaviorDefinitions: UFarmHarvestBehavior / UFarmWeedingBehavior / UFarmPestBehavior
│   └── 初始 bEnabled: false（未播种默认禁用）
```

**ActivityTags 可省略的源码依据**：`USmartObjectDefinition::Validate()`（SmartObjectDefinition.cpp:115）只检查①行为定义无空条目 ②Slot 必须有行为定义——**不检查 ActivityTags**。空 Tag 不影响注册/认领；卫星选点走自研状态查询（B 路径），不调 `FindSmartObjects`。若阶段 6 玩家侧用 GameplayInteractions 引擎查询，届时再补配。

### 4.3 动态挂载 = `SetSlotEnabled`（不是增删 Slot）

引擎 API（`SmartObjectSubsystem.cpp:1644`）：`bool SetSlotEnabled(FSmartObjectSlotHandle, bool)`

```
未耕地：  Plot=Disabled  Crop=Disabled
已耕地：  Plot=Enabled   Crop=Disabled（没作物可收获）
已播种：  Plot=Enabled   Crop=Enabled
```

- 资产 Slot 集合固定（实例化后不可增删），运行时用启用/禁用表达"当前可交互什么"
- 被禁用 Slot：查询不命中、不可认领
- **触发点**：`CellManager` 现有操作函数（Plow/Plant/Harvest）内同步调用

### 4.4 状态 → 启停映射（定稿：Slot 对应对象存在性）

**原则**：Slot 跟随“对象是否存在”，不承载“操作可行性”（成熟与否是内部状态，执行时校验）。

| 操作 | 对象变化 | Plot Slot | Crop Slot |
|---|---|---|---|
| 耕地 `PlowLand` | 地块对象出现 | **Enable** | — |
| 移除耕地 `RemoveLand` | 地块对象消失 | **Disable** | — |
| 播种 `PlantCrop` | 作物对象出现 | — | **Enable** |
| 收获 `HarvestCrop` | 作物仍在（Harvested 阶段） | — | 不变 |
| 移除作物 `RemoveCrop` | 作物对象消失 | — | **Disable** |

**注册策略（定稿）**：全量注册（6 万实例，Slot 默认 Disable，永不注销）→ 状态驱动 SetSlotEnabled。注册时机：`CreateMassCell` 完成后，建议分批（5000/帧）避免单帧卡顿。

**播种即启用 Crop Slot 的代价与缓解（B 路径下消除）**：原方案卫星查 ActivityTags 可能命中未成熟格子 → 白跑。B 路径选点**直接按状态枚举过滤**（卫星要收获 → 查 `ECropState::ReadyForHarvest` → 只拿成熟格子），**天然规避白跑**——此问题在 B 路径下不存在。

## 五、Slot 级锁语义（认领粒度）

**源码实据**（`SmartObjectRuntime.h`）：
- `FSmartObjectClaimHandle` = `SmartObjectHandle` + `SlotHandle` + `UserHandle` 三元组
- `MarkSlotAsClaimed(FSmartObjectSlotHandle, ...)` 入参是 **SlotHandle** → 锁挂在 **Slot** 上
- `FSmartObjectRequestResult`（查询结果）也精确到 Slot

| 场景 | 行为 |
|---|---|
| 双 Slot 方案：收获（锁 Crop）与灌溉（锁 Plot） | **可并行**（不同资源）✅ |
| 同 Slot 二次认领 | 失败（互斥）✅ |
| 除草（同时操作两者） | 双 Slot 都挂行为 + **claim 两个 Slot** |

**推论**：双 Slot 天然支持"灌溉与收获并行"；需要"格子级全互斥"时由游戏逻辑保证（或扩展锁范围）。

## 六、选点路径与行为落实（定稿：B 路径 + 方案 A）

### 6.1 选点路径决策（v1.2 新增：B 路径）

**决策**：卫星选点**不走引擎 `FindSmartObjects`/ActivityTags**，改为自研状态查询：

```
卫星决策层（StateTree/自研）
  → 直接问 CellManager：哪些格子状态满足？（ECropState::ReadyForHarvest / EPlotState::Plowed...）
  → 拿到坐标候选（位掩码体系，数据权威）
  → SmartObjectManager 提供 坐标→SlotHandle 映射
  → ClaimSmartObject(SlotHandle)（无需引擎查询）
```

**理由**：① 项目状态体系（位掩码 + fragment）已完备且是数据权威，卫星决策本就要读格子数据，选点自然基于状态；② 再引入 Tag 查询 = 维护两套“能否做”的真相；③ 规避 Tag 粗筛命中状态不满足格子的缝隙（选点直接按状态过滤）。

**边界**：ActivityTags 留空（Validate 不要求）；玩家侧（阶段 6）若用 GameplayInteractions 引擎查询需补配 Tag。

### 6.2 桥：荷载（Payload）是钥匙

`FCoordinatePayload` 随 `CreateSmartObject` 存入实例 → 认领后读 Slot 荷载拿到格子坐标 → 调 CellManager 操作接口。

### 6.2 定稿方案：行为 = 纯参数，执行放自定义 StateTree 任务

行为类只带参数（蓝图可配），执行在自定义任务。执行链路（收获示例，B 路径）：
```
卫星 agent StateTree
  → 自定义选点任务：查状态 → 目标坐标
      （CellManager 查 ECropState::ReadyForHarvest，不调 FindSmartObjects）
  → SmartObjectManager: 坐标 → SlotHandle 映射 → ClaimSmartObject（锁 Slot）
  → 自定义任务 ExecuteFarmAction
      ├─ 读 Slot 荷载 → FCoordinatePayload(X,Y)
      ├─ 等待 Duration（读 UFarmHarvestBehavior 参数）
      ├─ CellManager->HarvestCrop(FIntPoint(X,Y))   ← 复用现有接口，零重写
      └─ 完成 → 释放 Slot
```

**为什么不用 `USmartObjectMassBehaviorDefinition::Activate/Deactivate`**：项目操作是"操作格子"（格子是被操作对象），不是"格子自操作"；操作接口即时生效、带返回值，StateTree 任务直调最贴合。

### 6.3 行为类体系（操作定义，FarmSmartObjectTypes.h）

```cpp
// 基类统一声明操作耗时；派生类只留特殊参数；挂哪个 Slot 由资产配置决定
UCLASS(Abstract) class UFarmActionBehaviorBase : public USmartObjectBehaviorDefinition
{
    UPROPERTY(EditDefaultsOnly) float Duration = 1.0f;  // 操作耗时
};

UFarmHarvestBehavior    收获（空，仅类型标记）
UFarmIrrigationBehavior 灌溉（WaterAmount）
UFarmFertilizeBehavior  施肥（FertilityAmount）
UFarmPlowBehavior       耕地（空）
UFarmPlantBehavior      种植（CropID）
UFarmWeedingBehavior    除草（空）
UFarmPestBehavior       除虫（空）
```

- 空派生类有意义的：引擎 `GetBehaviorDefinitionByType` 按具体类匹配，空类提供类型区分
- 同 Slot 可挂多个不同操作类（源码：`BehaviorDefinitions` 数组 + `IsChildOf` 查找）
- 清除类操作（反耕地/移除作物等）属玩家编辑模式，AI 不执行，不建行为类

### 6.4 玩家路径（阶段 6）

玩家走 GameplayInteractions（`UGameplayInteractionDefinition` StateTree 资产）或直接调 CellManager——与 AI 共用执行层接口。

### 6.5 操作映射表

| 行为 | 调用接口 | 前置校验（接口内） |
|---|---|---|
| 收获 | `HarvestCrop(Coord)` | 成熟阶段 |
| 耕地 | `PlowLand(Coord)` | 无 FPlotStateFragment |
| 灌溉 | `WetLand(Coord)` | 已耕地 |
| 施肥 | `FertilizeLand(Coord)` | 已耕地 |
| 种植 | `PlantCrop(Coord, CropName)` | 已耕地 + 无作物 |
| 除草 | `ClearWeeds(Coord)` | 已耕地（双 Slot 都挂） |
| 除虫 | `ClearPest(Coord)` | 已耕地 |

## 七、操作层决策（v1.1 修正：请求化定稿）

### 7.1 历史决策与规模前提修正

**v1.0 结论**：保留命令式，不重写（当时基于几十颗卫星的前提）。

**v1.1 修正（2026-09-02）**：用户明确项目目标将扩张到**成百上千卫星**，且请求化架构本身更优（批处理、解耦、代码量小、支撑未来扫描式收获模型）→ **定稿：大规模下执行入口请求化**。

**性能账（澄清）**：操作吞吐受作物生长周期约束（千卫星 ≈ 每帧 2~8 次操作），游戏线程可承受——**请求化不是性能优化，是架构正确性**（格子修改回到 Mass 数据流）。

### 7.2 定稿架构：分层 + 请求化执行入口

```
玩家点击 ──→ CellManager::HarvestCrop(Coords) ──→ TryHarvestCell(Entity) ──┐
                                                                            │ 结算一份，两路径复用
卫星任务 ──→ defer.AddTag(FHarvestRequestTag, CellEntity)                  │
              → UCropHarvestProcessor（批量查询带请求 Tag 实体）            │
              → 成功/失败 → Signal 通知卫星 ──────── TryHarvestCell(Entity) ─┘
```

**组件职责**：
| 组件 | 职责 | 说明 |
|---|---|---|
| `CellManager::HarvestCrop(Coords)` | 玩家入口（保留，同步即时） | `GetCellEntity` + 调公共结算 |
| `CellManager::TryHarvestCell(Entity)` | **公共结算**（校验/查表/算价/改状态） | 从旧 HarvestCrop 主体抽取，玩家与处理器共用 |
| `FHarvestRequestTag` | 请求标记 | 卫星 defer 加到格子实体 |
| `UCropHarvestProcessor` | 批量执行器 | 查询带 Tag 实体 → 结算 → 移除 Tag → 发信号 |

**玩家路径保留直调**（低频 + 即时性）；**卫星路径请求化**（解耦 CellManager）。CellManager 仍是格子数据权威，处理器与它的耦合是数据访问（可接受），解耦的是卫星→CellManager。

### 7.3 规模分档（修正触发条件）

| 阶段/规模 | 卫星任务执行 | 说明 |
|---|---|---|
| 阶段 1~5（几十颗验证） | 命令式直调 CellManager | 先跑通语义，不提前重构 |
| 规模化前（数百~上千） | **Tag 请求 + 格子侧 Processor** | 架构卫生改造，支撑扫描式收获 |
| 玩家路径 | 始终直调（或阶段 6 走智能对象 High 优先级） | 低频 + 即时性 |

**触发条件修正**：❌ “卫星上百”（性能理由不成立）；✅ “批量结算/轨道扫描式收获模型出现”时才需请求化。

### 7.4 盲区与补齐方案

| 盲区 | 问题 | 方案 |
|---|---|---|
| 异步时序 | 请求化后卫星拿不到即时返回值 | 处理器发 Signal（HarvestCompleted/HarvestFailed），卫星订阅响应 |
| 玩家竞态 | 玩家直调与卫星请求同帧碰同格 | 玩家走智能对象（阶段 6），High 优先级抢占（见 7.5） |
| 操作无感知 | 现有操作大多无视返回值（项目缺陷） | 请求化 + 信号广播顺带修复：结果可感知可广播 |

### 7.5 玩家优先：引擎原生优先级抢占（源码实据）

`ESmartObjectClaimPriority`：None < Low < BelowNormal < Normal < AboveNormal < High

`FSmartObjectRuntimeSlot::CanBeClaimed`（SmartObjectRuntime.h:172）：
```cpp
return IsEnabled()
    && (State == ESmartObjectSlotState::Free
        || (State == ESmartObjectSlotState::Claimed
            && ClaimedPriority < ClaimPriority));  // 高优先级可抢占低优先级 Claimed
```

**配置（非自研）**：卫星 claim 传 `Normal`；玩家 claim 传 `High`。

**边界**：抢占仅在 `Claimed`（认领未开始用）生效，`Occupied`（正在用）不抢。

### 7.6 卫星统一重选出口

被抢占（Slot 失效回调）与操作失败（Failed 信号）**殊途同归**——都汇到同一动作：

```
释放锁 → 重选目标 → 重新安排任务
```

卫星状态机只需一个“重选”出口，两条失败路径共用。

## 八、Mass 通知机制四层分工 + MassSignals 生态位

### 8.1 四层通知机制

| 机制 | 模型 | 适用 |
|---|---|---|
| UE 委托 | 绑定回调（认识接收者） | 玩家输入→UI 等同步即时事件（不进 Mass 管线） |
| **MassSignals** | 命名信号广播（不认识接收者） | **一次性事件通知**（成熟/收获完成/占用变化） |
| Tag/Fragment | 数据驱动（处理器查询） | 持续状态（正在收获/已耕地） |
| FMassObserverProcessor | 实体生命周期观察 | fragment/标签增删回调 |

### 8.2 MassSignals = Mass 生态的"解耦事件委托"生态位

- 触发者只发 `(SignalName, Entity)`，**不知道谁响应**
- 订阅者 = `MassSignalProcessorBase` 子类按名订阅，批量并行处理
- 替代的是旧代码中"跨实体 `BindUObject`/`AddDynamic` 硬绑定回调"的生态位

### 8.3 项目应用场景（成熟通知，替代轮询）

```
现在：MatureCropQueue + 0.5s 定时器轮询 ❌
未来：CropGrowthProcessor 检测成熟
      → SignalSubsystem->SignalEntity("CropMature", CellEntity)
      → 订阅者响应（卫星调度器：安排收获任务）   ← 调度通知，非 Slot 启停
```

注：Crop Slot 启停由“播种/移除作物”驱动（见 4.4），成熟信号用于**任务调度通知**而非 Slot 状态。

### 8.4 适用边界（勿混用）

```
Signal（刚发生的一次性事件）      fragment/tag（持续现状）
  成熟了 ✅                       正在收获 ✅
  收获完成 ✅                     已耕地 ✅
  被占用/释放 ✅                  干旱中 ✅
  "请执行收获" ❌ → 命令调用/Tag 请求
```
