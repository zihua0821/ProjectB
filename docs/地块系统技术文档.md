# 地块（Plot）系统技术文档

**版本**: v1.0  
**更新日期**: 2026-08-04  
**分支**: MassCrop  
**关联系统**: Cell（单元格）、Crop（农作物）

---

## 一、系统概述

### 1.1 语义定义

**地块（Plot）** 是单元格（Cell）被玩家执行"耕地"操作后产生的**可种植土地**。地块在视觉上通过 `LandCellMesh`（土地网格）呈现，并携带完整的耕地状态。

地块的**生命周期**：

```
星球初始化（CreateMassCell）
    ▼ 全量创建所有单元格的 LandCellMesh 实例，Opacity=0 隐藏
单元格（Cell，无地块状态，土地隐藏）
    │ 玩家执行"耕地"（PlowLand）：添加 FPlotStateFragment + 还原透明度
    ▼
地块（Plot，土地可见）
    │ 耕地/浇水/施肥/杂草/虫害 等状态操作
    │ 种植作物 → 作物系统接管生长
    ▼
玩家执行"反耕地"（RemoveLand）→ 透明度归零、移除状态 → 土地重新隐藏
```

**地块实例不是按需创建的**：所有单元格的 `LandCellMesh` 实例在星球初始化时**一次性全量创建**（`CreateMassCell` → `BatchAddInstances`），初始 Opacity=0 隐藏；耕地操作只添加地块状态（`FPlotStateFragment`）并将透明度**还原为 1.0**，反耕地则将透明度归零并移除状态。

### 1.2 与 Cell / Crop 的关系

| 系统 | 关系 | 说明 |
|------|------|------|
| **Cell（单元格）** | 地块的**载体** | 地块存在于单元格实体上；视觉共享 `LandCellMesh` 实例 |
| **Crop（农作物）** | 地块的**消费者** | 种植前提是地块已耕地（`Plowed`）；作物消耗地块的湿度/肥力 |

- 地块状态（湿度、肥力、杂草、虫害）是作物生长系统的输入
- 作物种植后，地块与作物共享同一个 Mass 实体，通过不同 Fragment 组合区分角色

### 1.3 关键设计点

- **全量创建 + 隐藏**：地块实例在星球初始化时全量创建（`CreateMassCell` 一次性 `BatchAddInstances`），初始 Opacity=0 隐藏；耕地操作将 Opacity 还原为 1.0
- **状态位系统**：地块状态用位掩码（`EPlotState`）表达，可同时拥有多个状态（已耕地+已灌溉+有杂草等）
- **湿度/肥力双参数**：`MoisturePercentage` / `FertilityPercentage`（0~1），由操作增加、随时间自然流失
- **影子副本**：`PreStateData` 记录上次状态，用于检测变化、避免每帧无意义的视觉写入
- **CustomData 控制视觉**：Opacity（显隐）/ Wetness（湿润）/ Fertility（肥力）三通道
- **Mass Defer 机制**：所有状态修改通过 Defer 命令延迟到帧末执行，避免与处理器竞争

## 二、架构设计

### 2.1 模块组成

```
┌────────────────────────────────────────────────────────────┐
│                     UCellManagerComponent                    │
│  (挂载于 APlanetActor，负责地块操作分发与状态修改)           │
└────────────────────────────────────────────────────────────┘
        │ 耕地时添加 FPlotStateFragment；操作修改状态/参数
        ▼
┌────────────────────────────────────────────────────────────┐
│                    Mass Entity（地块所在实体）               │
│  FCellStaticFragment   —— 静态数据：坐标/变换/类型           │
│  FPlotRenderFragment   —— 地块渲染 ID（LandCellMesh 实例）   │
│  FPlotStateFragment    —— 状态位 + 湿度/肥力 + 影子副本      │
│  (作物 Fragment)       —— 种植后附加（与 Crop 系统共享）     │
└────────────────────────────────────────────────────────────┘
        │ 读取状态变化
        ▼
┌────────────────────────────────────────────────────────────┐
│                 UPlotVisualSyncProcessor                    │
│  检测 StateData != PreStateData → 更新地块 CustomData        │
└────────────────────────────────────────────────────────────┘
        │ 写入
        ▼
┌────────────────────────────────────────────────────────────┐
│  UISMManager → LandCellMesh 的普通 ISM 组件                 │
└────────────────────────────────────────────────────────────┘
```

### 2.2 Fragment 定义

**`FPlotRenderFragment`**（`Mass/CellMassFragments.h`）— 地块渲染状态：

```cpp
USTRUCT(BlueprintType)
struct FPlotRenderFragment : public FMassFragment
{
    FGlobalInstanceId InstanceId;   // 当前 LandCellMesh 实例稳定 ID
};
```

**`FPlotStateFragment`** — 地块动态状态：

```cpp
USTRUCT(BlueprintType)
struct FPlotStateFragment : public FMassFragment
{
    FPlotStateData StateData;       // 耕地、浇水、施肥、杂草、虫害等状态位
    FPlotStateData PreStateData;    // 影子副本：上次状态（用于变化检测）
    float MoisturePercentage = 0.0f;// 水分百分比 [0,1]
    float FertilityPercentage = 0.0f;// 肥力百分比 [0,1]
};
```

> **影子副本机制**：`PreStateData` 记录上一帧的状态位，`UPlotVisualSyncProcessor` 通过 `StateData != PreStateData` 判断是否发生状态变化，仅在变化时更新 ISM CustomData。

### 2.3 ISM 组件配置

地块土地网格在 `UCellManagerComponent::CreateMassCell()` 中通过 `BatchAddInstances` **一次性全量创建**（所有单元格实例同时创建）：

- **网格**：`FarmlandConfig->LandCellMesh`（单元格土地网格）
- **普通 ISM**（`bUseIncrementalISM` 不设置，默认 false）——**地块不使用增量 ISM 组件**，视觉更新走 `UpdateInstanceCustomData` 父类路径
- **CustomData floats**：`FarmlandConfig->NumCustomDataFloats`（见 4.2 数量一致性说明）
- **全量创建 + 隐藏**：实例数量 = 全部单元格数（`(NumLat-1) × NumLon`），初始 Opacity=0 整体隐藏；耕地操作由视觉处理器将 Opacity 还原为 1.0
- **分桶**：由 `UISMManager` 内置管理（见 4.6 分桶机制），是否触发取决于蓝图实际配置的实例数

## 三、数据流

### 3.1 地块创建（耕地）

`UCellManagerComponent::PlowLand(Coords)`（`CellManagerComponent.cpp` L521-544）：

1. 通过坐标获取 Mass 实体
2. 检查是否已有 `FPlotStateFragment`（已耕地则直接返回）
3. `Defer().AddFragment<FPlotStateFragment>` 添加地块状态
4. Defer 命令：设置 `Plowed` 状态位、`CellType = ECellType::Crop`

> **注意**：耕地操作**不创建 ISM 实例**——所有 `LandCellMesh` 实例已在星球初始化时全量创建（Opacity=0 隐藏）。耕地只是添加地块状态，视觉处理器检测到 `Plowed` 后把 Opacity 还原为 1.0 使土地显示。
>
> 地块创建使用 **Defer 延迟添加 Fragment**：处理器在下一帧才能查询到该实体，视觉更新随之生效。

### 3.2 玩家操作链路

```
BasePlayerController::OnLeftMouseClick
    └─ TraceForFarmlandAndCell → 命中单元格坐标
        └─ PlanetActor::HandleLeftMouseClicked(EditMode, Coords)
            └─ CellManagerComponent::HandleLeftMouseClicked
                ├─ Plow / UnPlow → PlowLand / RemoveLand
                ├─ Wet / UnWet   → WetLand / LandDried
                ├─ Fertilize     → FertilizeLand / ClearFertilize
                ├─ Weed / UnWeed → GenerateWeeds / ClearWeeds
                ├─ Pest / UnPest → GeneratePest / ClearPest
                ├─ PlantCrop     → PlantCrop（联动 Crop 系统）
                └─ HarvestCrop   → HarvestCrop（联动 Crop 系统）
```

所有操作遵循统一的前置校验链：

```
存在 FPlotStateFragment（已耕地）？
    ├─ 否 → 操作拒绝（未耕地不能浇水/施肥/种植）
    └─ 是 → 执行状态/参数修改（通常为同步修改或 Defer 命令）
```

### 3.3 视觉同步（UPlotVisualSyncProcessor）

`PlotVisualSyncProcessor.cpp` 每帧执行：

```
ForEachEntityChunk（需求：FCellStaticFragment + FPlotRenderFragment + FPlotStateFragment）
    └─ StateData != PreStateData？
        ├─ Plowed 变化     → Opacity（1.0 显示 / 0.0 隐藏）
        ├─ Watered 变化    → Wetness（湿润可视化）
        ├─ Fertilized 变化 → Fertility（肥力可视化）
        ├─ WeedInfested 变化 → 杂草渲染（预留）
        ├─ PestInfested 变化 → 虫害渲染（预留）
        └─ 更新 PreStateData
```

**CustomData 布局**（`PlotCustomData`，`Crops/CropData.h`）：

| 索引 | 常量 | 含义 |
|------|------|------|
| 0 | `Opacity` | 地块土地显隐（1.0 显示 / 0.0 隐藏） |
| 1 | `Wetness` | 湿润程度（浇水可视化） |
| 2 | `Fertility` | 肥力程度（施肥可视化） |
| - | `Count` = 3 | 每实例 float 总数 |

**反耕地状态清理**：当 `Opacity` 计算为 0（`Plowed` 被移除）时，处理器会 `Defer().RemoveFragment<FPlotStateFragment>`，将该实体恢复为普通单元格——地块状态随之整个清除。

## 四、关键实现细节

### 4.1 状态位系统

**`EPlotState`**（`Crops/CropData.h`）— 位掩码枚举：

| 状态 | 值 | 说明 |
|------|-----|------|
| `Empty` | 0 | 空地 |
| `Plowed` | 1<<0 | 已耕地 |
| `CropPlanted` | 1<<1 | 已种植 |
| `Watered` | 1<<2 | 已灌溉 |
| `Fertilized` | 1<<3 | 已施肥 |
| `WeedInfested` | 1<<4 | 有杂草 |
| `PestInfested` | 1<<5 | 有虫害 |

`FPlotStateData` 提供 `AddState` / `RemoveState` / `ToggleState` / `HasState` / `Reset` 等操作，以及 `==` / `!=` 比较（供影子副本检测）。

### 4.2 CustomData 数量一致性

- 代码按 `PlotCustomData::Count = 3` 构造每实例 CustomData（Opacity/Wetness/Fertility）
- `BatchAddInstances` 传入的 `NumCustomDataFloats` 参数来自 `FarmlandConfig->NumCustomDataFloats`（配置默认值 2）
- **注意**：`BatchAddInstances` 内部有严格校验（`CustomData.Num() == 实例数 × NumCustomDataFloats`），不匹配则**静默跳过写入**。配置值必须与 `PlotCustomData::Count`（3）保持一致，否则材质读不到任何数据

### 4.3 湿度与肥力

| 操作 | 效果 | 配置项 |
|------|------|--------|
| 浇水（WetLand） | `MoisturePercentage` 增加，设置 `Watered` | `IncreasedMoistureWithEachIrrigation`（默认 0.6） |
| 反浇水（LandDried） | 移除 `Watered` 状态 | - |
| 施肥（FertilizeLand） | `FertilityPercentage` 增加，设置 `Fertilized` | `IncreasedFertilityWithEachFertilization`（默认 0.6） |
| 反施肥（ClearFertilize） | 移除 `Fertilized` 状态 | - |

> **自然流失**：`NaturalMoistureLossPerSecond` / `NaturalFertilityLossPerSecond` 配置了地块水分/肥力的自然流失速率。旧版 `UFarmlandComponent` 在 Tick 中实现了该逻辑；当前 Mass 版本尚未有对应的流失处理器（见 7 章已知问题）。

### 4.4 与作物的联动

地块是作物系统的**前置条件与输入**：

1. **种植前提**：`PlantCrop` 要求地块存在 `Plowed` 状态且无作物 Fragment
2. **初始状态继承**：种植时按地块当前状态初始化作物状态（已灌溉 → 作物不缺水的状态位、有杂草 → 作物杂草状态等）
3. **资源消耗（预留）**：作物生长本应消耗地块湿度/肥力（`CropGrowthProcessor` 中消耗代码被注释，见 7 章）
4. **成熟收获**：作物成熟后自动收获 → `HarvestCrop` → 作物状态设为 `Harvested`

### 4.5 反耕地（RemoveLand）

`RemoveLand` 的前置校验：

- 存在 `FPlotStateFragment` 且为 `Plowed`
- **有作物时禁止反耕地**（通过 Archetype 组合检查 `FCropTag`）
- 移除 `Plowed` 状态、恢复 `CellType = ECellType::Empty`
- 视觉处理器检测到 Opacity 归零 → 移除 `FPlotStateFragment`，实体恢复普通单元格

### 4.6 分桶机制（内置在 UISMManager）

地块/作物/轮廓的 ISM 组件**统一由 `UISMManager` 管理分桶**——分桶逻辑内置在 ISM 管理器中，**与增量 ISM 组件本身无关**（`UIncrementalInstancedStaticMeshComponent` 只是单个组件，不含分桶逻辑）：

| 参数 | 值 | 说明 |
|------|-----|------|
| `FISMBucketGroup` | - | 一个 Mesh 对应的桶组（`Buckets` 数组，每个元素是一个 ISM 组件） |
| `INSTANCES_PER_BUCKET` | 2048 | 单个桶（ISM 组件）的实例容量上限 |
| `BucketingThreshold` | 4096 | 触发分桶的全局阈值（可用 `SetBucketingThreshold()` 调整） |

**分桶触发条件**（`BatchAddInstances`，`ISMManager.cpp` L148-149）：

```
已实例数 + 本次新增数 > BucketingThreshold（4096）？
    ├─ 否 → 单桶（场景1）：全部实例进入一个 ISM 组件
    └─ 是 → 分桶（场景2）：按 INSTANCES_PER_BUCKET（2048）切分为多个 ISM 组件
```

**实例定位与更新**：`FGlobalInstanceId = (BucketIndex, LocalId)`；`UpdateInstanceCustomData(Mesh, InstanceId, ...)` 通过 `BucketIndex` 定位到具体桶，只更新该桶内的实例。

**地块的实际分桶状态**：

- 地块实例数 = `(实际 NumLat-1) × 实际 NumLon`，**由蓝图中的 `DA_PlanetConfig` 实际配置决定**
- **代码头文件中的默认值（`NumLat=13, NumLon=36` → 432 实例）仅为预设**，蓝图中会被覆盖，实际值大很多
- 实际实例数是否超过 `BucketingThreshold`（4096）取决于蓝图配置：超过则自动分桶（按 2048/桶），未超过则走单桶路径

> **分桶对视觉更新的意义**：对普通 ISM，每次 `UpdateInstanceCustomData` 触发所在组件（桶）的全量重建；分桶后单桶最多 2048 实例，单次更新只重建所在桶的数据，避免整个 Mesh 全部实例的重建开销。地块因初始化时全量创建、耕地时按需还原透明度，视觉更新频率本身较低；分桶与否需以蓝图实际配置的实例数为准。

## 五、配置项（UFarmlandConfigDataAsset）

| 配置 | 默认值 | 用途 |
|------|--------|------|
| `LandCellMesh` | - | 地块土地网格 |
| `NumCustomDataFloats` | 2 | 每实例 CustomData 数量（**应为 3**，见 4.2） |
| `CellSize` | (400, 400) | 单元格尺寸（影响地块实例缩放） |
| `MinLatitudeScale` | 0.5 | 边缘纬度收缩系数 |
| `CellOffsetZ` | 0 | 单元格径向偏移 |
| `LandHeightOffset` | 30 | 单元格高度 |
| `NaturalMoistureLossPerSecond` | 0.001 | 水分自然流失速率（当前未实现） |
| `NaturalFertilityLossPerSecond` | 0.001 | 肥力自然流失速率（当前未实现） |
| `IncreasedMoistureWithEachIrrigation` | 0.6 | 每次浇水增加湿度 |
| `IncreasedFertilityWithEachFertilization` | 0.6 | 每次施肥增加肥力 |
| `WeedSpreadInterval` / `PestSpreadInterval` | 5.0 | 杂草/虫害扩散间隔（当前未实现） |
| `GrowthRate_*` | 0.5~0.7 | 各状态下的作物生长倍率 |
| `bInitAllLandCells` | false | 是否初始化所有地块 |

> 分桶相关参数（`INSTANCES_PER_BUCKET=2048`、`BucketingThreshold=4096`）定义在 `UISMManager` 中，不属于 `UFarmlandConfigDataAsset`（详见 4.6 分桶机制）；`NumLat`/`NumLon`（决定地块实例数）定义在 `UPlanetConfigDataAsset` 中，蓝图实际配置值会覆盖代码默认值。

## 七、已知问题与注意事项

1. **视觉更新代码被注释（当前地块无视觉反馈）**：`PlotVisualSyncProcessor.cpp` 中三处 `ISMManager->UpdateInstanceCustomData(...)`（Opacity / Wetness / Fertility）均被注释，导致耕地后土地不显示、浇水/施肥无视觉变化。恢复注释即可生效。
2. **CustomData 数量一致性**：`NumCustomDataFloats` 配置值必须等于 `PlotCustomData::Count`（3），否则 `BatchAddInstances` 静默跳过 CustomData 写入。
3. **自然流失未实现**：水分/肥力自然流失逻辑在旧版 `UFarmlandComponent` 的 Tick 中实现，当前 Mass 版本无对应处理器（`CropGrowthProcessor` 中注明"暂由自然流失处理器统一处理"，但该处理器尚未存在）。
4. **杂草/虫害视觉未实现**：`PlotVisualSyncProcessor` 中 `WeedInfested` / `PestInfested` 分支为空实现（预留），需配合杂草 Mesh / 虫害 Niagara 系统。
5. **作物资源消耗未启用**：`CropGrowthProcessor` 中地块湿度/肥力消耗代码被注释，作物当前不消耗地块资源。
6. **反耕地时序**：`RemoveLand` 同步修改状态，视觉处理器下一帧检测到 `Plowed` 移除后 Defer 移除 `FPlotStateFragment`，整体约 2 帧完成状态清理。
7. **操作前置校验**：所有地块操作（浇水/施肥/杂草/虫害/种植）都要求已耕地，未耕地时静默返回（无日志），调试时需注意。
8. **分桶触发取决于蓝图配置**：分桶机制内置在 `UISMManager`（`BucketingThreshold=4096`），触发与否取决于 `DA_PlanetConfig` 蓝图实际配置的 `NumLat`/`NumLon`（代码默认值 13/36 仅为预设，实际值大很多）；若触发分桶，视觉更新会通过 `FGlobalInstanceId.BucketIndex` 自动定位到对应桶，无需额外改动。
