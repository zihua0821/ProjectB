## 一、系统概述

### 1.1 定位与背景

**`UTimeSyncComponent`** 是一套**类 NTP 的客户端-服务器网络时间同步**实现：客户端周期性向服务器请求权威 UTC 时间，通过往返时延与网络对称度估算并维护"服务器时钟 − 本地时钟"的偏移量，对外（含蓝图）提供统一的同步时间读取接口。

**历史背景**：

```
2026-01-24  配置独立 Server 目标（联机为起步期的设计方向）
2026-01-25  2df396f 添加时间同步组件和接口
2026-01-26  78bccbe 完善本地时间功能与事件系统 + 简单时间 UI（TimeWidget）
2026-02 起  玩法转向单机农场（→ 球形星球 → Mass 重构），联机需求搁置
此后        模块未再改动（源码保持 Jan 版），保留于代码库
```

**技术留存价值**：RPC 往返采样、时间戳协议设计、网络对称度门控、接口/实现解耦（BlueprintNativeEvent）、复制组件挂载位置选择（PlayerController）——未来若重启联机需求，可直接以此为基座演进。

### 1.2 语义定义

| 术语 | 含义 |
|------|------|
| 同步 UTC 时间 | 以服务器时钟为准的当前 UTC 时刻（客户端 = 本地 UTC + 时间偏移） |
| 同步本地时间 | 同步 UTC 时间叠加本机时区偏移（`FDateTime::Now() − FDateTime::UtcNow()` 动态求得） |
| 时间偏移 TimeOffset | 服务器时钟 − 本地时钟（客户端维护；服务器端恒为 0） |
| RTT | 往返时延 = 客户端接收时刻 − 客户端发送时刻（含服务器处理时间，代码注释假设 ≈0） |
| 对称度 Symmetry | `min(d1, d2) / max(d1, d2)`——两个单向延迟的接近程度，用于判断"对称网络"假设是否成立 |

### 1.3 设计目标

- 客户端（无服务端权限）即可获得统一的权威时间，蓝图可直接消费；
- 同步对网络抖动有基本鲁棒性：对称网络用"对称平均延迟"估算时钟偏移，非对称样本走兜底分支（复核见 §六）；
- 低侵入：接口 + 组件两层，零玩法系统依赖。

### 2.2 接口层（`ITimeSyncInterface`）

五个 `BlueprintNativeEvent`（均为 `const`）——组件以 `_Implementation` 覆写，蓝图无需关心实现来源：

| 接口 | 返回值 | 语义 |
|------|--------|------|
| `GetSyncedUTCTime()` | `FDateTime` | 同步 UTC 时间 |
| `GetSyncedUTCTimestamp()` | `double` | 同步 UTC 时间戳（Unix 秒，小数） |
| `GetSyncedLocalTime()` | `FDateTime` | 同步本地时间（含时区偏移） |
| `GetSyncedLocalTimestamp()` | `double` | 同步本地时间戳（Unix 秒，小数） |

### 2.3 组件层（`UTimeSyncComponent`）

`UActorComponent + ITimeSyncInterface` 双继承；复制开启、**Tick 关闭**（`bCanEverTick=false`，全程定时器驱动）。

| 分组 | 成员 | 默认值 | 说明 |
|------|------|--------|------|
| 参数 | `TimeSyncStartSeconds` | 1.0 | 客户端延迟发起首次同步 |
| 参数 | `TimeSyncIntervalSeconds` | 10.0 | 同步周期（每次响应后重挂） |
| 参数 | `SymmetryThreshold` | 0.8 | 对称度接受阈值 |
| 参数 | `RttDeltaThreshold` | 20.0 | 两单向延迟差阈值（⚠ 量纲复核见 §6.2） |
| 事件 | `OnSyncedTimeUpdated` | — | 每次同步完成广播（UTC + 本地双值） |
| 事件 | `OnRttUpdated` | — | 每次 RTT 采样后广播（毫秒） |
| 状态 | `CurrentRtt` / `TimeOffset` / `LastClientSyncTime` / `bInitialized` / `SyncTimerHandle` | — | 运行态数据（私有） |

## 三、同步协议与算法（核心）

### 3.1 三时间戳模型

```
客户端                                            服务器
  │  T1 = UtcNow()（LastClientSyncTime 本地留存）      │
  │ ─── Server_RequestTimeSync(T1)  [Reliable] ───▶  │
  │  （RPC 参数随包携带 T1）                           │  T2 = UtcNow()（ServerUtcTime）
  │                                                  │  d1 = (T2 − T1) ms
  │ ◀── Client_ReceiveTimeSync(T2, d1)  [Reliable] ── │
  │  T3 = UtcNow()（ClientReceiveTime）                │
  │  d2 = (T3 − T2) ms；RTT = T3 − T1                  │
```

> 设计上是"三时间戳"简化版 NTP：服务器不单独回传"处理完成时刻"，服务器处理耗时被折叠进 RTT（注释假设 ≈0）。

### 3.2 偏移估算与对称度门控（`ProcessTimeSyncResponse`）

```cpp
// 1) 采样
d1 = (T2 − T1)   // 客户端→服务器单向（服务器侧计算）
d2 = (T3 − T2)   // 服务器→客户端单向（客户端侧计算）
RTT = T3 − T1    // 不含 d1/d2 的拆分
对称度 = min(d1, d2) / max(d1, d2)      // 任一 ≤0 时返回 1.0（按对称处理）

// 2) 门控与偏移更新
if (对称度 > SymmetryThreshold || |d1 − d2| < RttDeltaThreshold)
{
    // 对称网络：标准估算——服务器发送时刻 + 半程 RTT ≈ 服务器"现在"
    OneWayDelay = RTT / 2
    EstimatedServerNow = T2 + OneWayDelay
    TimeOffset = EstimatedServerNow − T3        // 服务器时钟 − 本地时钟
}
else
{
    // 非对称样本兜底（⚠ 复核点见 §6.1）
    TimeOffset = min(d1, d2)                    // 以最小单向延迟直接作偏移量
}

// 3) 收尾：广播 OnSyncedTimeUpdated → bInitialized = true → 重挂 10s 定时器
```

### 3.3 读取路径与兜底

```cpp
FDateTime GetSyncedUTCTime()
{
    服务器（HasAuthority） → 直接 UtcNow()          // 服务器即权威，无需偏移
    客户端未同步（!bInitialized） → 本地 UtcNow()    // 同步完成前的安全兜底
    客户端已同步 → 本地 UtcNow() + TimeOffset
}
```

### 3.4 定时策略

- 首次：`BeginPlay` 后延迟 `TimeSyncStartSeconds`（1s）发起；
- 周期：**单次定时器链式重挂**——每次"响应处理完成"后挂 `TimeSyncIntervalSeconds`（10s）的下一次（非循环定时器，天然避免请求堆积）；
- 服务器侧：`BeginPlay` 置 `TimeOffset=0`、`bInitialized=true`，全程不参与同步。

### 3.5 时区换算

```cpp
// 本机时区偏移 = 本地墙钟 − UTC（动态求得，天然跟随系统时区设置）
const FTimespan TimeZoneOffset = FDateTime::Now() - FDateTime::UtcNow();
SyncedLocalTime = SyncedUtcTime + TimeZoneOffset;
```

## 四、关键实现细节

### 4.1 RPC 路由与挂载位置

- 两个 RPC 均为 **Reliable**：`Server_RequestTimeSync`（Client→Server）与 `Client_ReceiveTimeSync`（Server→Client）；
- 组件 `SetIsReplicatedByDefault(true)`，构造期由 `BasePlayerController` 创建——**PlayerController 是每个客户端唯一且持有连接端点的 Actor**，是承载客户端 RPC 的标准位置（换到非连接 Owner 上 RPC 会路由失败）；
- 三时间戳全部通过 RPC 参数与本地采样传递（T1 上行、T2/d1 下行、T3 本地），无需共享时钟即可估算偏移。

### 4.2 权限统一封装

`HasAuthority()` 收敛为 `Owner->HasAuthority()` 单一判定：服务器分支（不请求 / 直接返回 UtcNow）、客户端分支（请求 / 偏移读取）均经此分流。

### 4.3 蓝图消费面

- 事件驱动：`OnSyncedTimeUpdated`（UTC+本地双值）、`OnRttUpdated`（RTT）——UI 可直接订阅刷新；
- 拉取式：经 `ITimeSyncInterface` 五个接口按需读取（`BlueprintNativeEvent`，蓝图侧无实现耦合）。

## 六、已知问题与改进方向（搁置期复核）

> 本节为 2026-10-14 梳理复核所记，**均未改动源码**——供后续接入/复用前裁定。

| # | 位置 | 复核点 | 建议方向 |
|---|------|--------|---------|
| 6.1 | 非对称兜底分支 | `TimeOffset = min(d1, d2)`——把"最小单向延迟"直接当作"时钟偏移"，两者量纲不同（偏移是两个时钟的差，时延只是网络耗时），该分支等效于**近乎不修正** | 改为"取延迟最小样本做偏移估计"，或维持上次偏移并对无效样本计数/落日志 |
| 6.2 | `RttDeltaThreshold` | 注释为"（秒）"，比较值实际是毫秒（`20` = 20ms）——注释与量纲不一致 | 统一注释或调整默认值语义 |
| 6.3 | 对称度判据输入 | `d1/d2` 混入**未校正的初始时钟偏移**（首同步时偏移可能远大于真实延迟），判据会失真；目前靠"非正值 → 返回 1.0"的兜底落到对称分支（恰好是正确路径），但该行为与注释语义不符 | 显式处理并注明，或用 NTP 标准式（含 T2−T1/T3−T2 联立）消参 |
| 6.4 | 偏移更新策略 | 单样本直接覆盖 `TimeOffset`——无中值/滑动平均/异常样本剔除；两次同步间隔内本地时钟自由漂移（无漂移率建模） | 滑动中值（如最近 N 样本）+ 亚稳滤波 + 漂移率估计 |
| 6.5 | RTT 纯净度 | RTT 含服务器处理时间与 Reliable RPC 排队时延；`FDateTime` 依赖系统墙钟，分辨率约毫秒级——小 RTT 场景下量化误差占比上升 | 区分服务器处理时段回传（四时间戳完整版 NTP）；必要时换高精度本地位点（`FPlatformTime` 单调钟）测短时延 |
| 6.6 | 工程细节 | `TimeSyncInterface.cpp` 为空实现文件（纯接口，正常）；头文件保留 UE 模板注释（"Fill out your copyright notice..."） | 复用前顺手清理文件头模板注释 |

**若重启联机需求**，建议的演进顺序：6.1/6.2 修正 → 6.4 滤波与漂移 → 6.5 精度分层（墙钟管偏移、单调钟管时延）→ 与游戏内时间体系（昼夜循环）的桥接设计（如真实时间驱动赛季/活动）。
