## 三、核心设计（现状即约定，改动需用户确认）

### 3.1 转场轨迹（方案 2：极坐标同步 + 两分量）

```
pos(α) = ComputeOrbitWorldPosition(轨道, Lerp(r0, r1, α), θ0 + Δθ·α)
       + 轨道法线 × Lerp(v0, v1, α)

离轨（Approach）：起点 = 实测显示位置（槽位世界点反算方位）
                 终点 = 悬停点（权威：格子法线 × (Rp + 悬停高度)，含平面外分量）
                 v: 0 → d_hover
回轨（Return）  ：起点 = 悬停点；终点 = 槽位相位 + ω·T（含 δ0 补偿）；v: d_hover → 0
时长 T = sqrt(Δr² + Δv²) / v_r     （v_r 在卫星配置资产 DA_SatelliteConfig，默认 2000 cm/s——N9）

关键性质：切向角速度恒 = ω（落点自动对准、汇入无冲击、相对角位置恒定）
当前方案不含贝塞尔——根因是首版“曲线计算/问题结构未理清”，而非曲线本身（10-03 结论）；
极坐标清晰化后，贝塞尔作为“未来路径优化的候选手法”保留评估价值（平滑/避让等场景）
注（10-02）：贝塞尔三件套/最近点判据/PhaseStartLocation/TransferControlFactor 等死代码已从代码库清理
（详见审阅清单 §5.2 A 组执行记录）
```

### 3.2 槽位（智能对象）

```
· 槽位数 = 每轨卫星数 × K（K=5，OrbitSlotMultiplier 可配）；槽 i 相位 = CurrentPhase + 360×i/槽数
· 初始分配：星 i 认领槽 i×K（相位恰好均分，起步布局与 K=1 时一致）
· 已认领后的槽位查询【一律按认领句柄】：
    GetOrbitSlotWorldPositionByClaim / GetOrbitSlotPhaseByClaim / ResolveSlotIndexByClaim
· FMassSatelliteOrbitFragment 只存 SlotClaimHandle（轨道槽）；格子认领句柄在 Task fragment（单句柄 CellClaimHandle——见 3.3）；ClaimedSlotIndex 已删除（单一事实源）
· 渲染取位优先级：① 覆盖位置（离轨/悬停/漂移）② 归属槽世界点（在轨/在途）③ 账面相位点（无槽回退）
```

### 3.3 认领生命周期（N10 单 Slot 化：整格单句柄——启停机制已整体删除）

```
选点：整格作业权一次认领 → 写【单句柄】CellClaimHandle（整格一席位，不区分域）
作业：Work 出队【只消耗 WorkQueue】；句柄保留至回轨 = "出勤账本"
      当前项时长 = 按项 EditMode 查具体行为类（ReadActionDuration——句柄恒为整格句柄）
      所有权检查 = 单句柄（IsOwnershipValid——失权 = 整单失败）
作业时长：按操作映射具体行为类（Harvest/Plant/Irrigation/Fertilize/Weeding/Pest/Plow）
      —— ReadActionDuration（查不到回退 DefaultActionDuration）
回轨：【起飞瞬间】由 Return::EnterState 统一释放句柄（唯一释放点，互斥期至起飞）
任务侧门卫：无作物（CropState=nullptr）→ 无缺口——卫星只服务【播种状态】的格子
选点：全格扫描（GetAllCoords）——活跃农田集合已删（N10）
```
> 背景：曾把 ClaimHandles（旧数组账本）与 WorkQueue 同步出队 → 回轨时清单已空 → Slot 泄漏 → 后续认领永远失败；
> M-1 收口批：数组账本 → 两域显式句柄；N10 单 Slot 化：两域 → 单句柄（CellClaimHandle）
> + 启停机制整体删除（Set/Is SlotEnabled / 委托 / 四广播 / 活跃农田集合）；PC 恒走认领协议

### 3.4 时机判据（都是"与显示同源"）

```
离轨（DepartWait）：显示位置与提前量点的【相位差】≤ 1.5°（角度域——低帧率不跨帧跳过）
   提前量点方位 = θ_hover − ω·T·dir（显示位置反算方位与之比较）
回轨（ReturnWait）：槽位由【群体决策分配】（规划器认领后写回句柄，本任务只消费）；
     等到"目标槽位实时位置"与"悬停点投影"重合（角度容差 3°）→ 起飞
回轨落点：Δθ = ω·T·dir + δ0（δ0 = 槽位相位 − 悬停点投影方位）→ 落点与槽位零偏差
```

### 3.5 收获后重播

```
CellManager::HarvestCrop → stage=Harvested + Timer 清零
CropGrowthProcessor → Harvested 阶段累加 Timer
CollectCellGaps → elapsed ≥ ReplantDelaySeconds(5.0f，FarmlandConfigDataAsset) → 产出 PlantCrop 缺口
PlantCrop(bReplant=true) → 沿用该格原 CropID 重播
```

### 3.6 轨道全局规划（方案 A；运行期收敛完成）

```
权威文档：docs/Mass/轨道全局规划_需求方案.md / _执行方案.md（v1.0）
运行期复盘：docs/Mass/轨道全局规划_运行期问题复盘.md（13 问题全录）

核心要点（含运行期修订）：
· K=5 槽位扩容 + 群体决策（Mass 帧序内驱动——USatelliteOrbitPlanProcessor；滚动节拍 1s；
  在途星按目标槽计"已到占位"；确定性、无状态）
· 落座乙案：等待角 ≤45° 过滤 → 插入后最小相邻间距最大 → 平局等待角小；决策即认领
· 漂移=同轨道加速前移/减速后移：前移 1×ω / 后移 0.75×ω（保底绝对速度 0.25ω，不停住）；
  时长夹[2,6]s；位移范围[3°,45°]；【前移优先】（P2——消除"相向穿越"与停住观感）
· 发单三件套：认领目标槽 + 释放旧槽 + 冻结显示覆盖
· 均匀化（阶段②，运行期重写为"消除过近"）：与最近邻居 ≥ 有效线 → 免动；
  只动挤对中可动一方；无动源则静默；独立 5s 节流；防撞=合并版
· 选点（运行期修正）：单向轴行程=到"提前量点（目标方位−ω·T）"的正向角距；跳过"已被认领"格
· 漂移探测→当场认领→统一"✓→Depart"（中断去作业；滑完经 DepartWait"无目标"自愈回 Cruise）
· 拒单策略：保持"聚焦未来"（无过阈候选不接单；饥饿兜底列为未来可选项）
```

## 六、已知易错点（改动前务必回看）

```
1. 双推进源：槽位相位与卫星相位是两条线（渲染锚点必须用槽位点）
2. 双字段不同步：同一事实只留一个字段（句柄 or 索引，不可并存）
3. 判据不同源：判据必须看"玩家看到的量"（实测显示位置），不能用公式反推点
4. 跨子空间：悬停点（格子法线，可在轨道平面外）vs 轨迹点（平面内）——必须补垂直分量
5. 运动目标：落点用"目标相位 + 偏差补偿"，不能用理想几何点
6. 数组双职责：同一数组不要同时做"待办清单"和"长期账本"
7. StateTree 子状态自动下沉：进入父状态会按顺序尝试进入子项——子状态须配"输入条件"拦截（否则无请求也进入→失败→回根→循环）
8. StateTree"选择行为"只在进入/完成时评估、不每帧重估——运行中突发请求必须用"Tick时转移"
9. Mass 下任务实例数据不能作转移条件绑定源（菜单仅全局参数）；跨节点数据用【评估器】
   （已验证可跑；但评估器只做"慢变数据源"（如漂移请求）——瞬时事实不得借它跨帧表达，见 12 条）
10. 漂移发单（请求+冻结）依赖状态树消费：消费端失效→卫星冻在原地；接到作业的星被作业流程自然接管（不卡）
11. 选点距离必须单向轴（身后=最远）；旧无向角距误选身后点→Depart 等一圈
12. 任务"瞬时事实"（刚认领了）绝不跨帧表达（评估器+条件转移=50% 竞态）——统一去向，让"无目标"自愈
13. 跨源角差（累积相位 vs 反算归一角）必须先归一（mod 360）再 FindDelta——单次修正会失效
14. 扫描/评分必须跳过"已被任何认领"的格子——否则悬挂认领会成为全场黑洞吸引子
15. 触发线在离散槽网格上有"不可满足/贴线"区间——取值需按星数验算（0.95 永动、20 星 0.8 贴 4 格）
16. 所有运行时驱动必须收编进 Mass 帧序（组件 Tick 只留注册期职责）——跨驱动源时序=事故温床
17. 悬停点权威链（轨迹终点=到达写入=作业悬停=回轨起点）任何一环的"近似"都会留下固定偏移
18. Mass StateTree 任务 dt = 墙钟差（MassStateTreeProcessors）——任何"跳过 tick 的暂停"恢复时必须
    重置 LastUpdateTimeInSeconds，否则暂停窗口计入 → 任务瞬间"飞完"（表现为瞬移）
19. Slate SpinBox 提交回调顺序：OnValueCommitted【先于】OnValueChanged（SSpinBox::CommitValue）——
    "提交即消费数据"的回调必须自己先落地本次值，不能依赖值变化回调先执行
20. 方向换算（顺时针/逆时针）：同一角度运算存在两类量——【沿运动方向量】（前移正）与【相位增量】
    （直接进参数方程，顺时针为负向前进）——两者差一个 dir 因子。规约：沿运动方向量→相位增量
    一律乘 dir；直接相位差（如 δ0=槽位−悬停）不得乘 dir。仅按逆时针验证会掩盖此类错误
    （2026-10-04：D5 顺时针缺陷修复——4 处换算统一 | 见审阅清单 D5）
21. Unity Build 同 TU 匿名命名空间重名：同模块两个 .cpp 的匿名 namespace 定义同名函数——Unity 合并后
    属于同一匿名命名空间 → C2084 重定义（分组抖动时才爆雷）。跨文件复用的小工具必须提为公共函数
    （10-06 实例：NormalizeAngleDegrees360 双实现 → 提取 BPFL；约定文档 §5.5 已补盲区）
22. TWeakObjectPtr 无 operator bool（引擎显式 delete）：弱指针判空必须 IsValid()；operator-> 可用但
    失效时解引用崩溃（前置 IsValid 守卫）；无隐式转换（getter 返回裸指针需 .Get()）；与裸指针 ==/!=
    比较受支持（10-07 S3 弱指针化 14 文件实践——编译验证通过）
23. Unity Build 分组抖动暴露"蹭头"：某 .cpp 无完整类型 include 却做值语义操作（TSoftObjectPtr 赋值/
    LoadSynchronous/Cast 等）——平时靠同 TU 其他 .cpp 的 include 泄漏"蹭"着编译通过；大量文件改动
    （注释批量修订/类增删/改名）触发 UBT 重新分组后泄漏消失 → C2027/C2679/C2338 爆雷。
    修法：使用点补"谁用谁 include"（10-13 实例：ProjectBGameInstance.cpp 补
    FarmlandConfigDataAsset.h / PlanetConfigDataAsset.h）
```
