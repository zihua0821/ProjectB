## 二、详细设计

### 2.1 选定暂停（独立暂停系统）

```
【载体】新 WorldSubsystem：USimulationControlSubsystem（~30 行——只持状态）
   void SetSimulationPaused(bool bPaused);              // PC 进/出编辑模式调用
   bool IsSimulationPaused() const;                     // 实例查询
   static bool IsSimulationPaused(const UWorld& World); // 便捷：处理器自检一行用
   private: bool bPaused = false;

【接线】PC：
   EnterOrbitEditMode → Subsystem->SetSimulationPaused(true)
   ExitOrbitEditMode  → flush 未落地改动（如有）→ SetSimulationPaused(false)

【白名单挂载——统一宏】（仅 4 个"世界演化"处理器，Execute 开头一行）：
   SIMULATION_PAUSE_RETURN(*Context.GetWorld());
   · USatelliteStateTreeTickProcessor（心跳——行为总闸）
   · USatelliteOrbitPlanProcessor（规划）
   · USatelliteOrbitMovementProcessor（槽推进 + 卫星相位）
   · UCropGrowthProcessor（作物生长）
   注：宏定义随子系统头：
       #define SIMULATION_PAUSE_RETURN(World) if (USimulationControlSubsystem::IsSimulationPaused(World)) return;
       宏 = 统一措辞 + 防手滑（等价于手写 if 检查，多一层封装）；
       白名单 = 宏的调用点（代码即清单；grep 宏名即列全）；跨体系通用
       （将来组件/Actor/子系统要纳入，同样一行宏——不挑体系）

【不动的系统】（默认不停——零改动）：
   格子视觉（含高亮 CellVisualSync）/ 作物视觉 / 地块视觉 / 卫星渲染同步（数据→渲染，
   空转无害且重建后下一帧即反映新构型）/ 玩家自由飞行、相机、输入、UI、昼夜循环

【已知细节】作业倒计时用墙钟（FPlatformTime）：暂停跨越倒计时窗口时，恢复后该项立即完成
   （可接受；若在意可后续改 DeltaTime 累计——不在本方案）
```

### 2.2 实时应用链（提交触发——决策 b）

```
【值变化过程】（保持现状，不动）：
  面板控件（键入/滚轮/箭头）→ WorkingData 更新 → PC->SetOrbitData → Manager->UpdateOrbitData
  → 只写 RuntimeOrbits + 广播（轨道线/范围可视化"节流刷新"——跟手）

【提交落定】（新增）：
  面板控件 OnValueCommitted（回车/失焦）→ PC->CommitOrbitChanges() → Manager->ApplyOrbitChanges()
  → 重建（销毁重建星+槽）→ 立即看到新效果

· PC 新增：void CommitOrbitChanges() const;
    { if (Manager = ResolveSatelliteManager()) Manager->ApplyOrbitChanges(); }
· 增/删轨（面板"+新建/删除"按钮）：点击 = 提交动作——保留现有"内部 Apply"（立即重建，
  暂停中重建可行）——语义与"提交时应用"一致，不额外改动
· Apply 按钮移除后，"生效"只剩两条路径：值提交 / 增删轨——全部实时可见
```

### 2.3 重建链三修复（核心）

```
① DestroyAllSatellites —— 归还认领（P2）：
   销毁实体前，遍历每个旧星：
     · FMassSatelliteTaskFragment：全部 ClaimHandles 逐个 ReleaseClaim（含重复句柄——幂等）
       （当前项句柄也在 ClaimHandles 账本内；无需单独处理——防御性可补 ClaimHandle）
     · FMassOrbitFragment：SlotClaimHandle 若有效 → ReleaseClaim
   注：ReleaseClaim 双清（账本 + 引擎 MarkSlotAsFree）；碎片空指针防御

② CreateSatellitesForOrbit —— 认领失败可见（P4）：
   TryClaimOrbitSlot 返回无效句柄 → UE_LOG Warning（含轨道名 + 星索引）
   （正常=零告警；出现即"槽注册不完整"信号）

③ RegisterOrbitSlots（SmartObjectManager）—— 显式销毁旧实例（P5）：
   重建前（Reset 表之前）：遍历旧 OrbitSlots 的 ObjectHandles →
     SmartObjectSubsystem->DestroySmartObject(Handle)
   注：替代现有"旧实例由引擎生命周期管理"的注释判断（该判断不成立——实例不自动销毁）
   （实施时核对引擎 API 签名：USmartObjectSubsystem::DestroySmartObject）
```

### 2.4 Apply 按钮与旧入口移除清单

```
· Widget：Apply 按钮（UI 构建处）+ OnApplyClicked（L400-407）+ 其内调用（L404）——删除
· PC：ApplyOrbitChangesToSatellites（L426-432）、OrbitApplyChanges（L357-363）——删除
  （若存在蓝图引用：加载/编译蓝图时会提示，随报随处理——或保留函数标废弃）
· Manager：ApplyOrbitChanges 保留（重建底层实现，由 CommitOrbitChanges / AddOrbit / RemoveOrbit 调用）
```

## 六、风险与注意

```
· 暂停为自建机制（不触碰引擎 SetGamePaused/TimeDilation）：玩家/UI/输入零影响
· 白名单若新增系统：加一行自检 + 子系统头注释备忘（代码即清单，无双事实源）
· 删除 PC 函数：若有蓝图引用，随报随处理（低风险——当前仅 C++ 内部引用已确认）
· DestroySmartObject 签名：以引擎实际 API 为准（实施时核对）
· 重建期间"暂停中"的瞬时视觉：重建完成后新构型即时呈现（符合"所见即所得"）
```
