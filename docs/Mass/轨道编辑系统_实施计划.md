## 二、关键设计

### 2.1 运行时轨道数据

```cpp
USTRUCT()
struct FRuntimeOrbitData
{
    FName  OrbitName;
    FVector Center = FVector::ZeroVector;    // 圆心 C（可偏移，不要求过球心）
    FVector Normal = FVector::UpVector;      // 平面法线 N（单位向量）
    float  OrbitRadius = 0.f;                // 轨道半径 r
    float  ServiceRadius = 0.f;              // 服务半径 s（默认 = 半格高）
    int32  SatelliteCount = 3;               // 卫星数（面板可调）
    float  AngularVelocity = 10.f;
    bool   bClockwise = false;
};
```

- **宿主**：`USatelliteManagerComponent` 扩展（卫星/轨道的天然归属）
- **初始化**：启动时从 `PlanetConfig->OrbitDefinitions` 转换
  （Transform.Location → Center；Rotation 轴 Z → Normal；Radius → r；s 默认 = 半格高）
- **资产不改**（编辑只改运行时副本；本期不做存档）

### 2.2 覆盖判定（管 ∩ 球面——共享函数）

```cpp
// 落位：SatelliteMassFragments.h（inline，与 ComputeOrbitWorldPosition 并列）
FORCEINLINE float ComputeDistanceToOrbitCircle(
    const FVector& Point, const FVector& OrbitCenter, const FVector& OrbitNormal, const float OrbitRadius)
{
    const FVector ToPoint = Point - OrbitCenter;
    const float Axial = FVector::DotProduct(ToPoint, OrbitNormal);
    const float Radial = (ToPoint - Axial * OrbitNormal).Size();
    return FMath::Sqrt(FMath::Square(Radial - OrbitRadius) + FMath::Square(Axial));
}

// 覆盖 = 距轨道圆 ≤ 服务半径
FORCEINLINE bool IsPointInOrbitCoverage(
    const FVector& Point, const FVector& OrbitCenter, const FVector& OrbitNormal,
    const float OrbitRadius, const float ServiceRadius)
{
    return ComputeDistanceToOrbitCircle(Point, OrbitCenter, OrbitNormal, OrbitRadius) <= ServiceRadius;
}
```

- **选点 Task 切换**：原"平面带"判定替换为本函数（Center/Normal 从 shared 的 OrbitTransform 换算；
  ServiceRadius 从 shared 新字段读）
- C=0（过球心）时与旧判定行为等价——**向后兼容**

### 2.3 环带求交算法（核心几何）

```
输入：C / N / r / s / 球面采样半径 Rs（= R + 抬升）

构造平面正交基：E1 = N 的任意正交向量，E2 = N × E1

对每个采样角 θ（0~2π，N 段，建议 128）：
    截面方向：D(θ) = E1·cosθ + E2·sinθ
    在截面平面内（2D 坐标：径向 x、轴向 y，原点 = 球心投影）：
        轨道截面点   = (r, 0)                      // 管中线
        管边界圆     = 圆心 (r, 0)、半径 s
        球截面圆     = 圆心 (0, -d)、半径 ρ = sqrt(Rs² - d²)    // d = dot(C, N)（C 的轴向分量）
    求两圆交点（标准解析公式）：
        两圆心连线方向上的投影 + 垂直方向的 ± 分量
        → 得该 θ 的"上边界点"和"下边界点"（世界坐标 = 平面内插值 + C 的其余分量）

拼接：上/下边界各 N 点 → 三角形带（2N 顶点，~2N 三角形）
边界情况：两圆无交点（管与球不相交）→ 该 θ 无点（整体为空则不生成）
```

## 附二：缺陷修复记录——悬停高亮“误涂相邻格”（v1.4）

**现象**：普通编辑模式悬停格 A → 切轨道编辑模式 → A（在覆盖内）显示异常，
相邻格出现“更亮/重合”（颜色被涂错）；有时触发有时不触发。

**历史背景（该缺陷代码的由来）**：
- 最初版本中“颜色更新”**嵌套**在 `if (bHighlightChanged)` 内 → “已高亮状态下切换编辑模式”
  （普通模式内的模式切换，状态不变仅颜色变）时颜色**无法更新**
- 第一次修复：把颜色更新改为**独立 `if (bColorChanged)`**（并列）→ 历史问题解决 ✅，
  但引入本缺陷（“新增+变色”同帧双真）

**根因（句柄代际 + 队列时点语义）**：

```
同一帧“新增实例”（PendingAdds，句柄本帧稍后（Add 执行后）才回写）与
“颜色更新”（PendingUpdates，读当前 InstanceId）同时发生时：
  PendingUpdates 携带的是【上一代实例】的旧句柄
  该句柄的槽位已被引擎复用给同桶的其他新实例（如相邻格 B）——ISM 槽位复用是正常行为
  → 执行阶段 Update 把颜色涂到 B 身上（时序组合不同 → 时好时坏）
```

**修复（else if + Add 同步 Last 颜色）**：
- 颜色 Update 改为 `else if (bColorChanged)`——仅在“状态未变”时独立发（此刻实例必然存在、句柄有效）
- Add 分支内同步 `LastHighlightColor`（颜色随 Add 的 CustomData 一并提交，不再对旧句柄发 Update）

**兼容性验证（历史需求未回归）**：

| 状态变化 | 颜色变化 | 修复后行为 | 结论 |
|---|---|---|---|
| 否 | 是 | Update（句柄有效） | ✅ 历史需求场景（模式切换换色） |
| 是（新增） | 是 | Add（颜色随 CustomData） | ✅ 原缺陷场景（不再读旧句柄） |
| 是（移除） | 是 | Remove（跳过颜色更新） | ✅ 比旧版更正确（对象已不存在） |
| 其余组合 | — | 与旧版一致 | ✅ |

**沉淀的不变量**：
> PendingUpdates 中的句柄，只可能来自“实例当前存在”的实体；
> 批处理设计：随创建写全属性（Add 带 CustomData）优于“先创建、再属性补齐”。

**附带修复**：ISMManager 在 Add 的“空桶→非空”时刻显式 `UpdateBounds()`（落实
“增量 API 不自动更新 Bounds 致剔除失效”的已知结论，单桶+分桶两条路径）。

## 附三：ISM 网格参数注册表（v1.5）

**背景**：ISM 组件参数（AttachParent / 禁用 Nanite / 阴影等）曾散落在各调用点各持一份
（预创建、处理器、卫星）——“值一致”仅靠巧合（同一 AttachParent 对象）；
且 `GetOrCreateBucket` 对“已存在的组/桶会忽略后续参数”——任何一处改动都会静默漂移
（不同桶挂到不同父组件 → 星球旋转时轮廓错位）。

**设计（一种网格一份参数，单一事实来源）**：
- 参数表本体：`ISMManager` 的 `FISMBucketGroup::CachedParams`（显式化，加 `bParamsRegistered`）
- 新接口：`RegisterMeshParams(Mesh, Params)`（唯一权威；重复注册不一致 → 告警）/
  `GetMeshParams(Mesh)`（查询）
- 语义：批量/组件接口传**空参数**（AttachParent == nullptr）→ 自动取注册值
- 兼容：未注册 + 传非空 → 以传入值首次定格（旧调用不破坏）
- 防漂移：已注册后传入不一致 → 每网格一次性 Warning（暴露绕过注册表的调用）

**注册时机（一处集中）**：
- `CellManagerComponent::PrecreateISMComponents`：地块 / 轮廓（+禁用 Nanite、不投影）/ 作物网格群
  ——注册与“预热桶 0”合一
- `SatelliteManagerComponent::Initialize`：卫星网格（父级 = 星球根、单桶）

**调用点统一（全部改为空参数取注册值）**：
地块（CreateMassCell）/ 轮廓（CellVisualSyncProcessor）/ 作物（CropVisualSyncProcessor）/ 卫星（RegisterRenderInstances）

**顺带**：CustomData 数量命名化——`CellOutlineCustomData::Count`（16）、`CropCustomData::Count`（3）
替换全部硬编码。

**备注**：`FarmlandActor`（旧地块体系）暂未纳入注册（其调用走“首次定格”兼容路径）；
旧体系退役时一并处理。
