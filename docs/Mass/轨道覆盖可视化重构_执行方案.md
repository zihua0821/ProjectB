## 三、目标形态

### 3.1 三字段删除（按需经 GetOwner）

```
· 删 .h 三缓存字段；使用点改 GetOwner 现取（低频路径——事件驱动后更低频）
  使用点清点：Initialize（订阅用）/ RebuildOrbitVisual / ComputeCoveredCells / RebuildCellHighlight
            / RefreshVisualization
· 建议内联辅助封装（命名实施时定，如 GetPlanetActor()——GetOwner 的 Cast 封装）保持使用点简洁
```

### 3.2 ComputeCoveredCells → BPFL + 混合色

```
· 迁入 UPlanetBlueprintFunctionLibrary（与 IsPointInOrbitCoverage 同处——几何判定库）
  签名（草案）：ComputeCoveredCells(const UCellManagerComponent* CellManager,
    const UPlanetConfigDataAsset& PlanetConfig, const TArray<FOrbitDefinition>& Orbits,
    TMap<FIntPoint, FLinearColor>& OutCells)
  ——类型在 N9 后为 FOrbitDefinition；批内 N9 先行 → 避免签名二次改（见七）
· 混合色：内层收集全部命中轨道色 → 求平均（累加 / 命中数）；去 break
  ——稳定（与列表序无关）；单轨命中 = 原色（退化一致）；无命中 = 不入 Map
· 调用点：组件 RefreshVisualization 改调 BPFL（原成员函数删除）
```

### 3.3 事件驱动按需重建 + 整体移除 Tick

```
· HandleRuntimeOrbitChanged(OrbitName) 直接处理（无脏标记、无 Tick）：
    存在于 RuntimeOrbits → RebuildOrbitVisual(名)
    不存在（被删）      → RemoveOrbitVisualInstances(名) + OrbitVisuals.Remove(名)（条目管理统一）
    覆盖刷新            → 全量重算 + diff（432 格轻量；写最小由 diff 保证）
· 全量路径保留：SetVisualizationEnabled(true) → RefreshVisualization（首建/开关）
· 删除清单：
    · Tick 三件套（bCanEverTick / bStartWithTickEnabled / SetComponentTickEnabled(false)）
    · TickComponent override + .h 声明
    · bPendingRebuild / TimeSinceRebuild / RebuildInterval（含详情面板配置项"重建节流"）
    · SetVisualizationEnabled 内的 SetComponentTickEnabled 调用
· 约定注释（类头）：调用端负责频率——本组件为无状态服务（收到事件即刷新）；
  未来高频源在源头解决（谁产生压力谁处理）
· 频率基准：调用端拖动 0.2s 节流（编辑链既有）；事件到达即刷新——与现状实际节奏一致
```

## 九、实施细化（10-12 讨论收敛——统一节拍器）

```
【背景修正（对方案 §3.3“调用端零改动”的修正）】
· 现状两条链：
  链 A（推送）：SetX 内直调 Push（每帧）→ 广播 → 组件【Tick 0.1s 节流】吸收（高频吸收器在组件内）
  链 B（重建）：RequestThrottledRebuild 0.2s（面板）→ CommitOrbitChanges → 卫星重建
· 删组件 Tick 后：链 A 每个值变化事件将直接驱动覆盖全量重算（每帧 ~10ms）——拖動卡死
· 结论：“节流归调用端”对【重建链】成立，对【推送链】不成立——需将推送收编进同一节拍器

【统一节拍器（源头单节流·下游零节流）】
· 唯一节流点：RequestThrottledRebuild →【更名 RequestThrottledUpdate】（0.2s）
     到点一帧内顺序执行：① PushWorkingDataToManager() → ② CommitOrbitChanges()（先推后建）
· 直达路径（用户落定操作·非高频·无需节流）：
     OnValueCommitted → SetX + CommitOrbitChanges（其内开场 Push 兜底——最终值必达）
     颜色落定路径（SColorPicker committed——实施时按 wiring 定）
· SetX×10 / ApplyPickedColor：删内部 Push（纯数据更新——推送职责上移至节拍器）
· 控件 OnValueChanged 回调层（SetX + RequestThrottledUpdate）：结构不变
· 贵活入口穷举闭合：Push 来源 = 节拍器到点 + Commit 兜底；Commit 来源 = 节拍器到点 + committed 直达

【ComputeCoveredCells 裁定（10-12）】维持全量版（节流配套后事件 ≤ 5Hz ≈ 现状 10Hz 的一半——
  用户“暂缓修复”口径延续；缓存优化不做）；混合色照做（④）
【颜色路径（10-12 收尾修订）】拖动色轮高频 → 轻节拍 RequestThrottledPush（只推不建）；
  关窗 OnColorPickerWindowClosed 兜底 Push（原方案“挂统一节拍器”会触发实体重建→卫星相位重置——已修订）
【零残留目标】bPendingRebuild / RebuildInterval / TickComponent / LastThrottledRebuildTime（旧名）
【验证补充】拖动流畅度（0.2s 节奏）+ 松手最终态正确落定 + 颜色拖动不卡
```
