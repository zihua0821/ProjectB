# 卫星离轨作业（方案 C）需求方案

> **状态**：**v1.0 —— 定稿**（全部决策已确认，无待抉择项；20 项决策见第十一节）：
> ① 中断规则（所有权检查三情况） ② 认领（一次认领全部 Slot） ③ 队列不做状态复核 ④ 主动奔赴关闭
> ⑤ 位置由任务侧计算（路径参数起飞时一次算好，飞行期间每帧仅曲线求值） ⑥ HoverHeight = 1000
> 待实施批准。
> **命名**：命名由 AI 决定（用户决定结构与职责的合理性）；结构性数值取值由用户拍板。
> **背景**：轨道编辑确立"同轨卫星共享角速度 ω"（物理约束）→ 现行的"在轨道上停驻作业"违反运动学自洽，且导致后车追尾。

## 一、核心结论与概念

```
结论：轨道 = 交通干线（恒定角速度，不破坏）；作业 = 离轨机动（飞入管辖范围悬停作业）
关键不变量：同轨同速 ⇒ 任意两星的"相对相位"恒定（回轨无碰撞的基石，无需任何调度器）
```

| 概念 | 定义 |
|---|---|
| **服务范围（管辖范围）** | 现行"覆盖带"语义升级：判定仍为平面带（唯一权威），表达"该轨道可作业的格子集合"；不再意味着"卫星必须停在带上" |
| **悬停高度 HoverHeight** | **星球配置**（PlanetConfigDataAsset）= **1000 cm（已确认）** |
| **悬停点 H** | `H = S + Normal × HoverHeight`（S = 目标格中心球面点）；**不落存储**——每次由"格子位置 + 悬停高度"现算 |
| **悬停层** | 半径 = `R_planet + HoverHeight` 的球面（离轨/回轨路径的中间层） |
| **虚拟相位** | 卫星离轨期间，其轨道角度按 ω 照常推进（只是位置不在轨道上）——回轨依据；**以独立字段显式记录**（不依赖"当前角度兼任"的隐式约定） |

## 二、状态流转（六状态；决策全部在状态树）

**状态定义（已确认）**：六个阶段统一为**卫星状态**（唯一状态枚举，写入 fragment 显式记录）；
原 `ESatelliteMoveState`（Idle/MovingToTarget/Paused）语义已被完全覆盖，**废弃**（实施时核对引用后移除）。

**设计原则（已确认）**：等待阶段提升为**独立状态**——"等什么、能否打断、打断去哪"全部在状态树资产里配置（决策可视化、可扩展），不硬写在任务代码内部。

```
Cruise（巡航 + 选点）
  · 位置由轨道角度决定（现状机制，不变）
  · 选中目标（服务范围内，评分选点 + 认领协议）后 → Depart
      ↓ 选中目标
Depart｜待发（等待离轨时机 = 最近点）
  · 位置：照常巡航（不控制运动）
  · 时机到 → Approach
  · 转换检查：Depart→Approach 转换时做所有权检查；失去所有权 → 回 Cruise（状态树配置）
      ↓ 时机到（且所有权仍有效）
Approach（离轨飞行：三次贝塞尔 → 悬停点）
  · 位置：路径求值（位置覆盖开启）
      ↓ 到达悬停点
  · 转换检查：Approach→Work 转换时做所有权检查；失去所有权 → 直接跳 AwaitReturn（已在悬停点）
Work（悬停作业：格内多操作队列依次执行）
  · 位置 = 悬停点 H（固定）
  · 队列 = 该格全部缺口操作（见第六节）；逐项执行（每项沿用行为定义 Duration）
  · 每个 action 前做所有权检查；失去所有权 → 跳 AwaitReturn（状态树配置）
  · 不做状态复核（队列构建时已确认缺口；所有权窗口内不会变化）
      ↓ 队列完成
AwaitReturn｜待回（等待回轨时机 = 虚拟相位点最近点）
  · 位置：保持悬停
  · 时机到 → Return
  · 中断：本版无额外中断规则（待回期间作业已完成，等待回轨即可）
      ↓ 时机到
Return（回轨飞行：三次贝塞尔 → 虚拟相位入轨点）
  · 位置：路径求值（位置覆盖开启）
      ↓ 到达入轨点（清位置覆盖）
Cruise
```

## 三、悬停点与行动时机

### 3.1 悬停点计算（已定）

```
输入：目标格坐标 → CellManager::GetCellWorldTransform → 格子中心
① S = 格子中心归一化方向 × R_planet          （球面点）
② Normal = S 的归一化（球面法线）
③ H = S + Normal × HoverHeight               （悬停点，与轨道无关）
```

### 3.2 行动时机：最近点触发（已确认）

```
问题：选定目标/任务完成即行动 → 卫星可能在星球背面，路径绕远、视觉突兀
机制（已确认）：
  离轨：选定目标后继续巡航，等到"当前相位点 ↔ 悬停点"距离最小的时刻（每圈一次）再出发
  回轨：作业完成后保持悬停，等到"虚拟相位点 ↔ 悬停点"距离最小的时刻再回轨
判据（纯数学，AI 提案）：相位方向与"悬停点在轨道平面的投影方向"重合（夹角 ≤ 容差）
等待上限：一整圈（一定会经过最近点）；本版不加"提前量"
承载（已确认）：离轨等待 = Depart 状态（专用等待任务）；回轨等待 = AwaitReturn 状态（另一专用等待任务）
            决策在状态树，任务只判定时机（不控制运动）
```

## 四、路径模型：三次贝塞尔（已确认）

### 4.1 控制点设计

```
离轨（轨道点 P0 → 悬停点 P3）：
  P1 = P0 + 轨道切线 × d        （出发沿轨道切向，不"急转"）
  P2 = P3 + 球面法线 × d        （到达时垂直下降，从格子上方落下）
回轨（悬停点 P0 → 入轨点 P3 = 虚拟相位对应点）：
  P1 = P0 + 球面法线 × d        （垂直上升）
  P2 = P3 + 轨道切线 × d        （末端沿轨道切向切入 → 入轨切向对齐自然成立）
d = k × |P0 → P3|（k 存于卫星管理组件统一配置，默认 0.35）
轨道切线：由 ComputeOrbitWorldPosition 同一参数化导出（含顺逆时针正负）
```

### 4.2 曲线求值

```
B(t) = (1-t)³P0 + 3(1-t)²t·P1 + 3(1-t)t²·P2 + t³P3
缓动：t 前套 smoothstep；飞行时长 = 路程 / 轨道线速度（无参数，已确认）
```

### 4.3 安全策略（三层）

```
① 最近点时机（第 3.2 节）→ 起终点夹角天然较小
② 控制点均取在悬停层外（|P1|、|P2| ≥ R + HoverHeight）
③ 兜底：曲线采样 N 点（如 16）校验 min|P| ≥ R + HoverHeight（纯算法）
```

**已否决方案（记录）**：三段式（径向-球面弧-径向）——语义清晰但不平滑（段间切线不连续）；两点直线——穿球风险。

## 五、回轨机制：虚拟相位（已确认）

> 决议：回轨采用"虚拟相位"（保持分配时的均匀关系）；"绝对 home 点"方案已否决（会破坏均匀关系，且需"等待安全窗口 + 插入检查"，回轨后间距会塌缩）。

```
前提：同轨所有卫星共享 ω（物理约束）
① 卫星离轨期间，其轨道角度按 ω 照常推进（虚拟相位，仅不写位置）
② 回轨点 P* = 虚拟相位对应的轨道圆上点
③ 因所有卫星同 ω：任一卫星与前后车的相位差恒定
   → 卫星回轨时，与前/后车的间距 = 离轨前的间距 → 天然无碰撞、无需插入检查、无需调度器
④ 均匀关系保持：分配时的均分关系在离轨→作业→回轨全程不变（回轨后队列恢复均分）
⑤ 入轨切向对齐：由贝塞尔控制点设计自然满足（P2 = P3 + 轨道切线 × d）
特殊：任一时刻允许同轨多颗卫星同时离轨（各自独立），互不影响
```

### 5.1 离轨/回轨数据流（深入）

```
角度（虚拟相位）：
  · Depart / Approach / Work / AwaitReturn / Return 全程，轨道角度按 ω 照常推进
  · 写入【虚拟相位字段】（显式记录；巡航时与当前角度一致）
位置（三类来源，由状态决定）：
  · Cruise / Depart：位置 = 轨道角度算得（现状机制，无覆盖）
  · Approach / Return：位置 = 贝塞尔求值（任务每帧写"位置覆盖"）
       —— 路径参数（起点/终点/控制点/时长）在起飞时一次性算好并写入 fragment；
          飞行期间每帧仅做曲线求值（~30 flops/卫星，无需预采样路径点）
  · Work / AwaitReturn：位置 = 悬停点（进入时写一次，之后保持）
渲染：渲染同步处理器检测"位置覆盖"标志——有则用覆盖位置，无则按角度算位置
完成：
  · 飞行结束（PhaseElapsed ≥ PhaseDuration）：写精确终点 → 状态切换（状态树转换）
  · 回轨完成：清覆盖标志 → 位置由角度接管（同一相位 → 连续无跳变）
```

## 六、作业队列（格内多操作，已确认）

> 决策：采用"档 1——格内多操作队列"（参考旧版 `BTTask_BuildTaskSatelliteQueue` 的设计）；
> 仅一个目标格，操作数有限，**不设队列上限**（档 2 跨格子出勤队列已搁置，数据不预留）。

### 6.1 队列构建（按该格状态，参考旧版流程）

**承载（已确认·合并）**：与选点在**同一任务**内完成（选点任务内调用，一次决策产出 TargetCoord + WorkQueue）；
构建逻辑为**独立函数**（`BuildCellWorkQueue`）——与选点算法解耦。

队列维度与现有选点判定【同源】（EvaluateCellNeeds 的六个维度）：
  成熟收获 / 已收获重播 / 杂草 / 虫害 / 缺水 / 缺肥
  · 暂不包含"主动耕地"（Plow）——耕地状态是"活跃农田"的前提，与现有选点逻辑保持一致
  · 顺序：按权重降序（与选点评分同源）
  · "选哪格"由评分决定（评分用于选点；队列构建只负责"该格要做什么"）

### 6.2 执行

```
Work 状态内逐项执行：
  取当前项 → （每个 action 前：所有权检查——失去则跳 AwaitReturn）→ CellManager::ExecuteFarmAction(项, TargetCoord)
  → 该项时长（行为定义 Duration）倒计时 → 出队（移除已完成项）→ 下一项 → 全部完成 → AwaitReturn
· 不做状态复核（已确认）：队列构建时缺口已确认；所有权保证独占（别人不会动它）
· 认领（已确认）：构建队列时把队列涉及的全部 Slot 一次认领（防抢）；释放时全部释放
  （认领对象 = 格子 × 操作类型（Slot）；语义上是"整格作业权"，两个 Slot 为实现细节）
```

### 6.3 与旧版的差异

```
· 旧版：TQueue<EEditMode> 在 Actor 上，无条件按状态排（执行前不复核，依赖操作幂等）
· 新版：队列存于 Mass fragment（TArray<TEnumAsByte<EEditMode>>，标准 FIFO 出队——不设索引字段）；
        不做状态复核（已确认）——所有权独占保证队列项不会失效；每个 action 前仅做所有权检查
· 旧版选点与构建是两个任务（因 EQS 异步——查询需等待）；新版选点同步 → 合并为一个任务（已确认）
```

### 6.4 EQS 演进约定（已确认，两条）

```
约定一：将来 MassEQS 替换的是"选点算法"本身（Processor 风格：查询结果写 fragment）；
        "构建队列"函数不在替换范围内——保持不动
约定二：目标相关数据保持 fragment 化（TargetCoord / WorkQueue 均在 FMassSatelliteTaskFragment）；
        EQS Processor 写入 → 状态树读取，天然兼容（无需改状态机结构）
备注：EQS 异步化后若需要"等待选点结果"，可在 Cruise 之后加过渡状态（本次不加）
```

## 七、轨道有效性校验（已搁置——后续独立需求）

> 本轮不做（用户拍板）：校验逻辑未来放**轨道管理组件（UOrbitManagerComponent）**，与轨道编辑联动提示；
> 以下公式与设计保留备查。

**要求**：轨道（巡航圆）必须整体位于悬停距离之外，否则为无效轨道并提示。

```
设：圆心 C（|C| = 圆心到球心距离，允许多轨道偏移）、轨道半径 R_orb、星球半径 R_planet
轨道圆到球心的最近距离：D_min = | ‖C‖ − R_orb |        （圆上点的最小模长）

有效条件：D_min > R_planet + HoverHeight
即：     | ‖C‖ − R_orb | > R_planet + HoverHeight
（等价形式：‖C‖ − R_orb > R_planet + HoverHeight  或  R_orb − ‖C‖ > R_planet + HoverHeight）
```

**提示位置与形式**（搁置——未来定）：
- 方案 a：编辑面板实时提示（参数区下方显示警告行，红色文本"轨道低于悬停高度，无效"）
- 方案 b：Apply（重建卫星）时拒绝 + 弹提示
- 建议：a + b 双层（编辑时提示，应用时校验）

## 八、边界情况

| 情况 | 处理（已确认） |
|---|---|
| 作业中被玩家抢占（认领协议） | 所有权检查（已确认）：Work 每个 action 前检查，失权 → 跳 AwaitReturn |
| 离轨前后目标失效（Depart / Approach 期间） | 所有权检查（已确认）：Depart→Approach 失权回 Cruise；Approach→Work 失权跳 AwaitReturn |
| 作业中轨道被编辑（参数变化） | 不影响进行中的卫星（现行机制：ApplyOrbitChanges 才重建）；轨道被删除时随重建清理 |
| 作业中轨道被删除（RemoveOrbit） | 卫星随 ApplyOrbitChanges 销毁重建 → 安全 |
| 多星同轨同时作业 | 允许（各自虚拟相位独立推进） |
| 目标格被其他卫星完成 | 由认领协议保证互斥（现行机制不变） |

## 九、参数（定稿）

| 参数 | 说明 | 建议 |
|---|---|---|
| HoverHeight | **星球配置**（PlanetConfigDataAsset）= **1000 cm（已确认）** | 与 ServiceDistance 默认同量级 |
