## 补丁 001：类级导出 FPrimitiveInstanceDataManager（❌ 已移除 2026-08-19）

| 项 | 内容 |
|----|------|
| **日期** | 2026-08-06 |
| **文件** | `Engine\Source\Runtime\Engine\Public\InstancedStaticMesh\ISMInstanceDataManager.h` |
| **位置** | `FPrimitiveInstanceDataManager` 类声明（约 L44） |
| **内容** | 类声明加 `ENGINE_API`：`class ENGINE_API FPrimitiveInstanceDataManager : public FInstanceIdIndexMap` |
| **目的** | 统一导出该类**全部非内联成员**（`Add` / `RemoveAt` / `RemoveAtSwap` / `TransformChanged` / `CustomDataChanged` / `FlushChanges` 等），供项目增量 ISM 组件（`UIncrementalInstancedStaticMeshComponent`）在游戏模块中调用，替代原"getter + Add 单独导出"两个零散补丁 |
| **影响** | 零行为影响（仅添加导出标记）；需引擎全量重编 |
| **升级重打** | 重新添加 `ENGINE_API` 到类声明即可（约 30 秒） |

### 补丁代码

```cpp
// 之前：
class FPrimitiveInstanceDataManager : public FInstanceIdIndexMap

// 之后：
class ENGINE_API FPrimitiveInstanceDataManager : public FInstanceIdIndexMap
```

### 说明

- **已删除类内所有方法级 `ENGINE_API`**（MSVC C2487：类级导出后成员不能再单独声明 dllexport）。已删除：构造函数、`SetMode`、`GetMode`、`HasAnyInstanceChanges`、`GetOrCreateProxy`、`MarkForRebuildFromLegacy`、`GetAllocatedSize`
- 内联方法（`FORCEINLINE` / `inline`：`HasAnyChanges`、`GetState`、`ValidateMapping`、`ResetComponentDirtyTracking`）不参与符号导出，原样保留

### 移除记录

- **2026-08-19 已手动移除**：旧增量组件 `UIncrementalInstancedStaticMeshComponent` 已于 M-5 清理中删除，本补丁的导出目的已不存在；源码已还原为 `class FPrimitiveInstanceDataManager`（无 `ENGINE_API`）。**升级引擎时无需重打本补丁**。
- 若未来仍需读取引擎变更集（`FInstanceAttributeTracker`），按下方附注重新添加 getter 补丁即可。

### ⚠️ 附注：变更集读取（getter 已移除，P2 需时再补）

原补丁方案中包含一个 getter：

```cpp
FORCEINLINE const FInstanceAttributeTracker& GetInstanceUpdateTracker() const { return InstanceUpdateTracker; }
```

**该 getter 已随本次清理删除。** 注意：类级导出**不会改变私有成员的可访问性**——`InstanceUpdateTracker` 仍是 `private`（类内 L211），游戏模块（含派生组件）**无法直接访问**。

若 P2 阶段需要读取引擎变更集（`FInstanceAttributeTracker`），需**重新添加该 getter 补丁**（位置：类 public 区），或改用其他导出方法间接获取。

## 补丁 002：修复 UpdateInstanceTransformById 参数错位

| 项 | 内容 |
|----|------|
| **日期** | 2026-08-19 |
| **提交** | `9c096042607b`（引擎仓库 5.5 分支本地提交） |
| **文件** | `Engine\Source\Runtime\Engine\Private\InstancedStaticMesh.cpp` |
| **位置** | `UInstancedStaticMeshComponent::UpdateInstanceTransformById`（L3399-3400） |
| **内容** | 调用 5 参版 `UpdateInstanceTransform` 时显式传 `bMarkRenderStateDirty=false`，`bTeleport` 正确落在第 5 参 |
| **目的** | 修复引擎 bug（JIRA UE-231099，官方修复提交 ce24c23badd6）：4 参版 `UpdateInstanceTransformById` 将第 4 参 `bTeleport` 按位置误传为 5 参版的 `bMarkRenderStateDirty`，传 true 即触发组件级渲染状态全量重建，与增量路径初衷相悖 |
| **影响** | 行为修复：增量变换更新不再误触发全量重建；仅 .cpp 改动，增量编译即可（无需全量重编引擎） |
| **升级重打** | **5.6+ 官方已修复（5.6/5.7/5.8/ue5-main 已逐一验证），无需重打**；5.5 分支未 backport，5.5.x 需保留本补丁 |

### 补丁代码

```cpp
// 之前：
UpdateInstanceTransform(PrimitiveInstanceDataManager.IdToIndex(InstanceId), NewInstanceTransform, bWorldSpace, bTeleport);
// 之后：
UpdateInstanceTransform(PrimitiveInstanceDataManager.IdToIndex(InstanceId), NewInstanceTransform, bWorldSpace, false, bTeleport);
```

### 说明

- 与官方修复提交 ce24c23badd6（ola olsson，2024-12-03，JIRA UE-231099）的 `.cpp` 部分逐字一致；官方提交中顺带的 5.4 弃用接口清理**未**纳入本补丁
- 规避方式（`GetInstanceIndexForId` + 5 参版显式传 `false`）为 5.5 下的等效替代，已记录于需求文档 C-2；打补丁后增量变换更新可直接使用 ById API，无需规避

## 补丁 004：UBlackboardKeyType_Struct 静态成员加 AIMODULE_API 导出宏

| 项 | 内容 |
|----|------|
| **日期** | 2026-04-10 |
| **提交** | `f9e6cb02b365`（引擎仓库 5.5 分支本地提交） |
| **文件** | `Engine\Source\Runtime\AIModule\Classes\BehaviorTree\Blackboard\BlackboardKeyType_Struct.h` |
| **位置** | 类内 public 静态成员/方法声明（L21-27） |
| **内容** | `InvalidValue` / `GetValue` / `SetValue` 三个静态声明添加 `AIMODULE_API` 导出宏 |
| **目的** | 修复跨模块链接错误：外部模块访问 `UBlackboardKeyType_Struct` 静态成员时符号未导出 |
| **影响** | 零行为影响（仅加导出标记）；需重编 AIModule 及依赖模块 |
| **升级重打** | 重打时检查官方是否已补导出宏，已有则跳过 |

### 补丁代码

```cpp
// 之前：
static const FDataType InvalidValue;
static FConstStructView GetValue(UBlackboardKeyType_Struct* KeyOb, const uint8* RawData);
static bool SetValue(UBlackboardKeyType_Struct* KeyOb, uint8* RawData, FConstStructView Value);

// 之后：
static AIMODULE_API const FDataType InvalidValue;
static AIMODULE_API FConstStructView GetValue(UBlackboardKeyType_Struct* KeyOb, const uint8* RawData);
static AIMODULE_API bool SetValue(UBlackboardKeyType_Struct* KeyOb, uint8* RawData, FConstStructView Value);
```

### 说明

## 补丁维护规范

1. 每次修改引擎源码，**必须**在此文档登记（编号递增）
2. 引擎升级后，按清单逐条重打补丁
3. 补丁应尽量小、零行为影响、只增不改
4. 涉及引擎头文件修改后需**全量重编引擎**
