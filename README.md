# ProjectB

**基于 Unreal Engine 5.5.4 与 Mass Entity 的球形星球农场模拟**

> 在整颗星球上耕作 —— 玩家开垦农田，AI 卫星舰队沿轨道巡航，自动完成播种、浇水、施肥、除草与收获。

| 引擎 | 语言 | 平台 | 开发分支 |
|---|---|---|---|
| UE 5.5.4（本地源码构建 + 自维护补丁） | C++ | Windows · DX12 / SM6 | `MassCrop` |

---

## 项目简介

ProjectB 是一个以**球形星球**为舞台的农场经营模拟原型：

- 星球表面按经纬网格划分为数万个单元格，玩家在球面上开垦、灌溉、施肥、种植、收获；
- 一队由 **Mass Entity** 驱动的卫星沿轨道巡航，自主认领格子、规划轨道、执行农事作业，形成"缺什么补什么 + 成熟自动收获 + 收获自动重播"的农业自动化闭环；
- 玩家与卫星共享同一套格子数据与智能对象作业权协议——玩家可随时抢占 AI 正在作业的格子。

项目围绕两条技术主线持续演进：

1. **大规模实例化渲染** —— 自建 `ISMManager`，以球面空间分桶 + 引擎原生增量 API 支撑 5.4 万格子的渲染与高频更新；
2. **纯实体 AI 系统** —— 卫星"无 Actor"化：Mass Fragment 承载数据、Mass StateTree 编排决策、智能对象协议仲裁作业权。

当前版本聚焦星球农场模拟与卫星自动化系统。

## 核心特性

### 球面星球与网格系统
- 经纬网格划分星球表面（当前资产配置约 **5.4 万单元格**；单元格数 = (纬线数 − 1) × 经线数），一维化索引寻址
- 屏幕拾取：射线与球面二次方程求交，直接从鼠标位置解算格子坐标，不依赖碰撞体
- 单元格高亮面片：平面面片 + 顶点偏移（CustomData 传四角球面坐标），GPU 端弯曲为贴合球面的梯形

### 农场玩法闭环
- 编辑模式体系：耕地 / 灌溉 / 施肥 / 杂草 / 虫害 / 种植 / 收获（含各自的反向操作），底部工具栏切换、颜色随模式映射
- 地块状态位掩码（`EPlotState`）+ 湿度 / 肥力双参数自然流失
- 作物 5 阶段生长（Starter → A → B → C → 收获）与品质评分，DataTable 数据驱动
- 昼夜循环与时间倍率、星球能量系统、行星存档（`USaveGame`）
- 地面 / 飞行两种 Pawn + HUD（时间、编辑工具栏、作物选择器）

### 卫星 AI 作业系统（Mass）
- **纯实体**：无 Actor，Fragment 承载数据，ISM 渲染
- **Mass StateTree 六状态机**：Select → DepartWait → Approach → Work → ReturnWait → Return（+ 漂移任务）
- **转场轨迹**：极坐标同步模型（切向角速度守恒、落点零偏差），替代初版贝塞尔方案
- **轨道全局规划**：K=5 槽位扩容 + 群体决策（确定性、无状态、滚动节拍）+ 漂移（加速前移 / 减速后移）与均匀化防撞
- **覆盖判定**：轨道覆盖带几何运算替代物理 Overlap 查询；覆盖可视化事件驱动、无 Tick
- 多轨道、多卫星编队（耐力回归测试覆盖 3 轨 30 星）

### 轨道编辑系统
- 运行时 Slate 编辑面板（`SOrbitEditorPanel`，UMG 包装），编辑模式内暂停仿真、落定后按轨重建生效
- 轨道增删与几何 / 槽位参数编辑，可视化开关（槽位球 / 轨迹 / 服务范围 / 覆盖）

### 大规模渲染底座（ISMManager）
- 球面空间分桶：格子坐标 O(1) 映射到桶（每桶 ≤ 2048 格），桶包围盒紧凑、视锥剔除生效
- 双维度分桶：空间（球面网格）+ 逻辑组键（卫星"一轨一桶"）
- 引擎原生增量路径：`AddInstancesById` / `RemoveInstancesById` / `SetCustomDataValueById` 等 ById API
- 空桶事件驱动停用 + 组件级池化，无每帧轮询

### 工程质量体系
- `docs/` 60+ 份文档：需求方案 → 执行方案 → 技术文档 → 复盘 → 审阅，全流程归档
- 代码审阅双体系：时间线审阅（P1~P8 提交演进）+ 模块审阅（M1~M8 结构走读）
- 编码约定、Debug 性能验证避坑指南、引擎补丁清单、语义索引维护工作流

## 技术亮点

### 1. 大规模 ISM 渲染：球面空间分桶 + 引擎增量 API

- **问题**：5.4 万格子的轮廓 / 土地 / 作物三类实例化数据同屏，剔除失效时 GPU 提交量成为唯一显著瓶颈
- **方案**：外部管理器承载分桶（不侵入引擎 ISM）——分桶输入为业务原生的格子坐标（严格同格同桶、无浮点边缘误差），每桶 ≤ 2048 格，桶列边界对齐 0° 经线规避包围盒跨圈
- **深度**：读引擎源码定位 UE 5.5.4 `UpdateInstanceTransformById` 参数错位 Bug（JIRA UE-231099，5.6+ 已官方修复），补丁与规避方案登记于引擎补丁清单
- **验证**：挡位表 + A/B 对照实验——7 万实例压力场景中，分桶 + 视锥剔除生效 **60+ FPS**（默认视角 40–48 FPS；剔除失效对照仅 10–20 FPS），游戏线程 tick 仅约 **1ms**（CPU 侧远未饱和）
- 详见 [`docs/渲染体系/ISMManager技术文档.md`](docs/渲染体系/ISMManager技术文档.md)

### 2. 纯实体卫星 AI：Mass + StateTree

- **无 Actor 架构**：fragment 数据层 + ISM 渲染 + Mass StateTree 决策，Fragment 按"变更频率"拆分以降低缓存失效
- **源码级发现**：`UMassStateTreeProcessor` 仅在收到订阅信号时 Tick（无信号不执行）——等待 / 轮询类任务必须外部驱动，据此设计心跳 Processor
- **EQS → 纯数据迁移**：原行为树 / EQS 三段式目标选择迁移为"候选集合 + 几何覆盖带硬过滤 + 状态 / 距离评分"，无物理查询
- **转场链路**：极坐标同步轨迹，切向角速度恒定，落点自动对准、汇入无冲击
- 详见 [`docs/卫星系统/交接文档_卫星转场链路.md`](docs/卫星系统/交接文档_卫星转场链路.md)

### 3. 智能对象认领协议（玩家与 AI 共享格子）

- 读引擎源码（`USmartObjectDefinition::Validate`）确认 ActivityTags 非必需，自建"坐标 → Slot 句柄"O(1) 映射，跳过引擎查询开销
- 5.4 万格子作业席位注册（单 Slot 化：整格一席位）；玩家 High 优先级可抢占卫星 Normal
- "意图委托"规避操作后的 Defer 时序问题（操作方广播启停意图、管理器订阅执行）
- 选点即认领、回轨时统一释放——单句柄账本杜绝 Slot 泄漏

### 4. 球面几何与渲染正确性

- **为什么不用 HISM**：项目网格体基本为 Nanite——HISM 的“距离 LOD 批次切换”职责被 Nanite 取代，且 HISM 与 Nanite 互斥；因此统一走普通 ISM + 自建空间分桶，承担“实例空间组织与剔除”职责（与 Nanite 分工互补：分桶控渲染线程提交量，Nanite 优化 GPU 绘制）
- **球面分桶的 AABB 膨胀分析**：三来源量化（切向跨度 / 径向弧高 / 方向错位），角跨度约束方案使弧高降 5~20 倍；Nanite 网格在 PIE / 打包两种剔除路径下的生效性完成源码级查证
- 覆盖带模型、平面外（法线）分量、δ0 相位补偿等球面数学问题的完整推导与复盘
- 详见 [`docs/渲染体系/球面AABB剔除精度问题与解决方案.md`](docs/渲染体系/球面AABB剔除精度问题与解决方案.md)、[`docs/渲染体系/Mass视觉与自建ISM管理器_技术选型.md`](docs/渲染体系/Mass视觉与自建ISM管理器_技术选型.md)

## 快速开始

**环境要求**

- Unreal Engine 5.5.4（本地源码构建版；项目经 GUID 关联引擎，含《引擎补丁清单》所述补丁）
- Visual Studio 2022（或 Rider），Windows 10 / 11
- 支持 DX12 / SM6 的显卡

**构建与运行**

1. 右键 `ProjectB.uproject` → **Generate Visual Studio project files**；
2. 编译 `ProjectBEditor` 目标（Development Editor）；
3. 打开 `ProjectB.uproject`，默认地图为 `Content/StartMap.umap`；
4. PIE 运行。

**操作**

- 鼠标左键：对悬停格子执行当前编辑模式的操作；
- 底部工具栏：切换编辑模式（耕地 / 灌溉 / 施肥 / 杂草 / 虫害 / 种植 / 收获）；
- 支持地面与飞行两种 Pawn（增强输入 `IMC_Default` / `IMC_Flying`）；
- 轨道编辑模式：暂停仿真，在面板中编辑卫星轨道，落定后按轨重建应用。

## 开发流程

项目采用**文档驱动的协作开发**方式，代码与文档同步演进：

1. **需求方案 → 执行方案**：先形成需求文档与执行方案，确认后才进入实施；
2. **实施 → 运行验证**：代码交付后在实际环境中运行验证，性能场景有专门的挡位表与对照实验方法；
3. **复盘 → 审阅**：对缺陷与关键决策写复盘文档；代码走"时间线审阅 + 模块审阅"双体系；
4. **沉淀**：所有方案、技术文档、Bug 复盘、审阅报告归档于 [`docs/`](docs)——即全过程协作产物。

开发由人主导计划、决策与运行验证，AI 承担草案、实现与问题修复。
